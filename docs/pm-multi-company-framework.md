이 표는 표본 6개 기업의 질적 비교다. 시장 전체의 통계적 대표성, 합격 확률, 공식 공통 평가 척도를 주장하지 않는다. 채용 공고·실무 인터뷰·직무 소개를 구분하며, 경력직 책임 수준을 신입의 필수 조건으로 전이하지 않는다.

## 2. 공통 관점과 다른 관점

공통적으로 읽을 것은 고객 문제의 근거, 선택한 방향, 본인 책임, 확인한 결과/학습이다. 하지만 그로스 PM은 행동·지표·실험, 서비스/플랫폼 기획은 정책·운영·예외·의존성, 신사업/B2B PM은 사용자와 구매자·사업 가치·도입 과정을 더 깊게 보여줘야 한다.

따라서 화면은 13개 체크리스트를 세로로 펼치지 않는다. **임팩트 브리프 → 기회·사업 판단 / 서비스 구조 / 지표·실험 / 출시·실행 책임**의 탐색형 포트폴리오로 구성한다. 읽는 관점을 선택하면 순서가 바뀌지만 자료나 역량 점수를 변경하지 않는다.

| 보여줄 가치 | 구체적인 시각 요소 | 추출 데이터 |
| --- | --- | --- |
| 관찰에서 기회를 골랐는가 | 대상별 관찰→해석→기회 인사이트 맵 | research |
| 사용자 가치와 사업 가치를 연결했는가 | 사용자↔가치↔비용 부담자, 수익/비용·충돌 | businessModel |
| 비교하고 포기했는가 | 같은 기준으로 읽는 대안 비교표 | alternatives |
| 화면 뒤의 운영까지 생각했는가 | 고객·접점·운영·시스템·예외의 레이어 표 | serviceBlueprint |
| 구현·검수가 가능한 기획인가 | RULE과 ACCEPTANCE를 분리한 정책 명세 | requirements |
| 성과를 만드는 행동을 이해했는가 | 선행지표→결과지표, 가설·측정 정의·보호 지표 | metricLinks |
| 검증 후 방향을 바꿨는가 | 실험 조건과 실제 관찰·후속 결정 | experiments + pmMetrics |
| 출시와 운영을 책임졌는가 | 이정표·범위·의존성·출시 기준의 기록 | releases |
| 제약·이견·위험을 처리했는가 | 조율 경로, 리스크 목록, 수정과 학습 | collaboration + risks + troubleshooting |

이 시각화 형식은 FitPoly의 제품 설계상 해석이다. 각 기업이 이 양식 자체를 요구했다고 주장하지 않는다.

## 3. 이전 구현과 실제 차이

- PM 전용 화면의 긴 세로 목록을 교체했다. 기존 경험도 즉시 브리프와 탐색 UI로 읽으며, 상세 산출물 부재를 이유로 화면 전체를 이전 형식으로 되돌리지 않는다.
- 그동안 공통 슬라이더가 남아 있던 `StructuredResult`의 PM 핵심 경험 탭도 동일한 보드로 교체했다. 다른 직군의 슬라이더는 유지한다.
- 경험 결과와 직군 특화 보기에도 같은 보드를 연결한다. 프로젝트·역할·파일 사이드바는 보존한다.
- 추출 스키마를 v2로 확장했다. 자료에 맞는 3~5개 산출물을 깊게 추출하고 불필요한 배열은 비우도록 한다. 새 상세 산출물은 원문 재분석이 필요하다. 기존 데이터에서 가상의 블루프린트·지표 관계를 합성하지 않는다.
- 재추출 버튼은 PM에게 계속 제공한다. 자료를 보완한 뒤 사용자가 다시 실행할 수 있다. 자동 유료 호출은 하지 않는다.
- 인쇄는 모든 관점·사례·출처를 표시한다. 공통 내보내기도 신규 필드의 내용을 보존한다.

## 4. 검증 범위

실제 계정·운영 DB를 건드리지 않고 합성 자료로 로컬 UI를 확인한다. 전체 페이지 모바일 가로 넘침, 표 내부 가로 스크롤, 관점 전환, 키보드 사례 전환, 원문 열기, 요약 편집, 계획/관찰 구분, 인쇄, 내보내기를 검증한다. 기업 자료의 내용은 추출 지침의 설계 근거이며 사용자 포트폴리오의 경험 근거로 섞지 않는다.
