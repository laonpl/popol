## 0. 요약 (TL;DR)

- **1크레딧의 실제 AI 원가는 $0.0001 = 약 0.14원**으로 코드에 고정되어 있다 (`CREDITS_PER_USD = 10000`).
- 현재 판매가는 크레딧당 **2.08~3.00원** → AI 원가의 **15~21배**로 팔고 있다.
- 부가세·PG 수수료·AI 원가를 모두 빼도 **패키지 마진율 81~83%** (전량 소진 가정 = 최악의 경우).
- 크레딧 단가의 손익분기점은 **약 0.16원/크레딧**. 지금 가격은 손익분기의 13~19배라 가격 인하 여력이 매우 크다.
- 가장 큰 리스크는 **검색 그라운딩 비용($0.035/건 ≈ 350크레딧 상당)이 크레딧에 미반영**된 것. 무료 한도(1,500건/일) 내에서는 0원이지만, 규모가 커지면 마진을 직접 갉아먹는다.
- 기능별 단가는 **실측 완료** (§4-2): 채용공고 분석 평균 707C(원가 102원), 핵심 경험 추출 705C, 전체 경험 분석 2,000~3,200C, 포트폴리오 맞춤 첨삭 2,231C. 모든 기능에서 마진율 94%+ 확인.

**크레딧에 미반영된 비용 (중요):**

| 항목 | 단가 | 현황 |
|---|---|---|
| 검색 그라운딩 (Gemini 2.5) | **$35 / 1,000건** = $0.035/건 ≈ 49원 ≈ **350크레딧 상당** | 유료 티어 기준 1,500건/일 무료, 초과분 과금. **현재 크레딧 차감에 미포함** |

그라운딩은 `callProFirstWithSearch` 2곳에서 사용: 경험 분석 Step1(개요), 시장 리서치. 즉 경험 1건을 풀로 분석하면 그라운딩 2건이 발생할 수 있다. 본 서비스는 Vertex AI(Express) 경유라 무료 한도 적용 조건이 Developer API와 동일한지 **[검증 필요]** — Google Cloud 청구서에서 "Grounding" 항목을 확인할 것.

## 5. 패키지별 마진 — 정확 계산

**가정:** ① 표시가는 부가세 포함 → 매출(공급가액) = 가격 ÷ 1.1, ② PG 수수료 3.3% (PortOne 카드/간편결제, 결제액 기준), ③ 구매 크레딧 **전량 소진** = 최악의 경우 (미소진분은 전부 마진), ④ $1 = ₩1,400.

| | starter (1,000C / ₩3,000) | standard (5,000C / ₩12,000) | pro (12,000C / ₩25,000) |
|---|---|---|---|
| 공급가액 (VAT 제외) | 2,727원 | 10,909원 | 22,727원 |
| PG 수수료 (3.3%) | −99원 | −396원 | −825원 |
| AI 원가 (전량 소진) | −140원 | −700원 | −1,680원 |
| **공헌이익** | **+2,488원** | **+9,813원** | **+20,222원** |
| **마진율 (결제액 대비)** | **82.9%** | **81.8%** | **80.9%** |

- 여기에 빠진 것: 고정비(서버·도메인 등 월 ~₩50,000 수준, 구 문서 §5 참고), 무료 크레딧의 잠재 원가(가입자당 최대 322원), 그라운딩 초과분.
- 무료 크레딧까지 반영한 "유료 전환 1명당 손익": standard 1팩 기준 9,813 − 322 = **+9,491원**. 즉 결제 1건이 무료 사용자 약 30명의 AI 원가를 커버한다.

## 6. 가격 설정 기준표 — 크레딧 단가별 마진

마진율 공식 (결제액 대비): **m = 0.876 − 0.14 ÷ P** (P = 원/크레딧, VAT 1/1.1 + PG 3.3% + AI 0.14원 반영)

| 크레딧 단가 P | 마진율 | 의미 |
|---|---|---|
| **0.16원** | **0%** | **손익분기점** — 이 밑으로 팔면 팔수록 손해 |
| 0.30원 | 40.9% | |
| 0.50원 | 59.6% | |
| 1.00원 | 73.6% | 현행 대비 절반 이하 가격으로도 70%대 마진 |
| 1.50원 | 78.3% | |
| 2.08원 (현 pro) | 80.9% | |
| 2.40원 (현 standard) | 81.8% | |
| 3.00원 (현 starter) | 83.0% | |

**환율 민감도:** 환율이 ±100원 움직여도 크레딧당 원가는 0.13~0.145원 범위 → 마진율 변화 ±0.3%p 수준. 환율은 사실상 무시 가능한 변수다.

**결론: 마진은 가격의 제약이 아니다.** 0.5원/크레딧까지 내려도 60% 마진이 남는다. 가격은 원가가 아니라 ① 지불 의사(현재 결제 0건의 원인 파악), ② 경쟁가(Wrtn Pro ₩9,900/월 등), ③ 심리적 앵커(₩3,000 진입가) 기준으로 정하면 된다.

| 크레딧을 얼마까지 내릴 수 있나? | 조정 후 손익분기 **0.64원/C**. 현 판매가는 손익분기의 3.3~4.7배 |
| 가격을 올려야 하나? | 마진 관점에선 불필요. 문제는 **전환(결제 0건)**이지 마진이 아님 |
| 다음 액션은? | ① `credit_cost_report.js`로 기능별 실측 → 기능 고정가 검토, ② 그라운딩 과금 반영, ③ pending 결제 9건 원인 분석 |

**진단:** 취준생 도구의 월 지불 수용선은 ₩6,000~₩15,000 수준이다. 조정 전(×10,000) 체감가는 전체 경험 분석 1건 ≈ 5,800원, 채용공고 분석 1건 ≈ 1,700원으로 — standard 1팩(₩12,000)이 "분석 2건이면 소진"되는 구조였다. 무료 2,000C로는 전체 분석 1건도 못 끝낸다(실측 2,000~3,200C). **결제 전환 0건의 구조적 원인**으로 판단.

### 9-2. 조정 내용

`billingService.js`의 `CREDITS_PER_USD` 기본값: **10,000 → 2,500** (요금제·패키지·지급 크레딧은 변경 없음)

- 1크레딧 원가: $0.0001(0.14원) → **$0.0004(0.56원)**
- 같은 AI 사용량에 대한 차감 크레딧이 **1/4**로 줄어듦 → 기능당 체감가도 1/4
- 기존 지갑 잔액은 그대로 (차감만 싸짐 — 사용자에게 유리, 마이그레이션 불필요)
- 배포 환경에서 `CREDITS_PER_USD` 환경변수가 설정돼 있으면 그 값이 우선이므로 **Render 환경변수에 구값(10000)이 없는지 확인 필수** (로컬 `.env`에는 없음 — 확인 완료)

### 9-4. 조정 후 마진 (전량 소진 = 최악 가정, VAT+PG 3.3% 차감)

마진율 공식: m = 0.876 − **0.56** ÷ P

| 패키지 | 원/크레딧 | 공헌이익 | **마진율** |
|---|---|---|---|
| starter ₩3,000 | 3.00원 | +2,068원 | **68.9%** |
| standard ₩12,000 | 2.40원 | +7,713원 | **64.3%** |
| pro ₩25,000 | 2.08원 | +15,182원 | **60.7%** |

- 손익분기 크레딧 단가: **0.64원/C** — 현 판매가는 여전히 3.3~4.7배 위
- 무료 크레딧 잠재 원가: 가입자당 최대 2,300C × 0.56원 = **1,288원** (조정 전 322원에서 4배 증가 — 무료 체험의 실질 비용. standard 결제 1건이 무료 사용자 약 6명을 커버)
- 그라운딩 미과금 리스크(§7-1)의 상대적 비중 증가: 그라운딩 1건(49원)이 공고 분석 1건 매출(437원)의 11% → 규모 확대 전 과금 반영 권장 유지

### 9-5. "구독 서비스와 결이 다른데 비교가 유효한가?" — 검증 논리

§9-1의 구독 서비스 비교는 **원가 구조가 아니라 지불 의사(₩6,000~15,000/월)의 앵커**로만 사용했다. 원가·마진은 자체 실측값(§4-2)으로 독립 계산했다.

**크레딧 종량제는 구독형보다 구조적으로 안전하다:** 구독형은 헤비 유저의 무제한 API 사용이 역마진을 만들지만, 우리는 모든 사용량이 계량 차감된다. 1크레딧 원가 0.56원을 2.08~3.00원에 판매 = **원가의 3.7~5.4배** — 사용자가 많이 쓸수록 마진이 비례해서 쌓인다.

**단, API 종속이라서 비교 분석에 안 잡히는 누수 3개가 진짜 리스크다:**
1. 그라운딩 미과금 (§7-1) — 공고 분석 1건 매출의 11% 상당
2. 실패·타임아웃 호출 — 과금은 성공 시에만 확정이지만 Gemini는 실패 요청의 생성분도 청구. 실패율만큼 원가 가산 (현재 미계측 — GCP 청구서와 `총_AI원가_USD` 대사로 추정 가능)
3. 무료 크레딧의 실현금화 — 가입자당 최대 1,288원이 실제 API비로 지출됨

**민감도:** pro 패키지(2.083원/C)의 마진이 0이 되는 실효 원가는 크레딧당 1.83원 = 계량 원가의 **3.3배**. 누수가 계량 원가의 +30%여도 pro 마진 52.6%. 즉 누수 채널이 원가를 3배 이상으로 불리기 전까지는 전 패키지 흑자 유지.

### 9-6. 검증 체크리스트 (배포 후)

1. Render 환경변수에 `CREDITS_PER_USD` 구값이 남아있지 않은지 확인
2. 배포 후 아무 AI 기능 1회 실행 → 거래 기록의 `requestedCredits`가 `usdCost × 2500`인지 확인
3. 2주 후 `node src/credit_cost_report.js` 재실행 → 기능별 평균 크레딧이 본 표의 1/4 수준으로 떨어졌는지 확인
4. 전환 지표 추적: 무료 크레딧 소진 도달률, 소진→충전 전환율 (조정의 성패 판단 기준)
