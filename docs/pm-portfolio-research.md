# PM 산출물 중심 경험정리 개편 · 2026-09-09

이 문서는 1차 개편 기록이다. 후속 다기업 비교와 현재 탐색형 포트폴리오 설계는 [다기업 기반 PM 프레임](./pm-multi-company-framework.md)을 기준으로 한다. 이번 후속 구현은 토스를 기준 기업에서 제외하고 6개 기업의 다른 맥락을 구분했다.

## 자료 확인과 해석 범위

- [토스 Product Owner 기업솔루션 채용](https://toss.im/career/job-detail?job_id=7774510003): 고객 조사에서 문제·요구사항을 도출하고, MVP 범위와 로드맵을 정의하며, 복잡한 정책을 제품으로 구현하고, 출시·성장 및 이해관계자 합의를 이끄는 역량을 요구한다. 이력서에서는 구체적인 문제·가설·실행·결과와 개인 기여를 설명하도록 안내한다. 실제 고용주가 공개한 기준으로 사용했다.
- [Taylor McCaslin의 Social Job Searching](https://www.taylormccaslin.com/portfolio/social-job-searching/): 본인이 채용 과제로 만들었고 Indeed에 합류했다고 밝힌 원문이다. 문제·경쟁 조사·목표·스케치·와이어프레임·목업·예외 상태·개선 및 측정 계획을 연결한다. **합격한 직군은 Interaction Designer이며 PM 합격 사례로 표기하지 않는다.** 인접 제품 설계 직군의 증거 연결 방식만 참고했다. 기대 효과를 실측 성과로 간주하지 않았다.
- [Taylor McCaslin의 Indeed Apply WordPress Plugin](https://www.taylormccaslin.com/portfolio/indeed-apply-wordpress-plugin/): 사용자 마찰과 해결 아이디어, 실제 동작하는 산출물·소스 연결을 확인했다. 활동 목록보다 결과물을 직접 검토할 수 있는 구성을 참고했다.
- [Mark Progano 공개 포트폴리오](https://mprogano.com/): 제품 구조, 사용자 흐름, 전략, 시스템 및 분석을 연결하는 제품 실무자 사례다. 특정 회사 합격 사실을 확인한 사례는 아니다.

외부 큐레이션이 '성공한 PM 포트폴리오'라고 소개하더라도 원문에서 확인한 직군·성과만 인정했다. 이번에 열람한 자료만으로 한국 PM 합격자 포트폴리오를 검증했다고 주장하지 않는다. 아래 구성은 위 자료를 FitPoly 요구사항으로 해석한 것이며 합격을 보증하는 공식 양식이 아니다.

## 화면 및 추출의 대응

| 평가받는 판단 | 구조화해 추출할 내용 | 결과물 표현 |
| --- | --- | --- |
| 고객·사업 문제 이해 | 대상, 맥락, 신호, 문제, 사업적 이유 | 문제 브리프 |
| 우선순위와 범위 결정 | 실제 대안, 채택·제외, 기준, 트레이드오프 | 대안별 비교 기록 |
| 서비스 구조 설계 | 원문 순서의 단계, 주체, 기존·변경 행동, 예외 | 사용자 흐름·전후 비교 |
| 실행 가능한 기획 | 요구사항, 조건·분기·처리 정책, 인수 기준, 책임 | REQ 번호가 붙은 정책 명세 |
| 실험과 검증 | 가설, 방법·대상·기간, 사전 기준, 관찰, 후속 결정 | 실험 기록 |
| 영향과 성과 해석 | 기준값, 목표, 실측, 측정 범위, 해석 한계 | 성과 리포트 |
| 협업·조율 | 상대, 이견, 본인 행동, 합의 | 조율 기록 |
| 문제 해결과 학습 | 문제, 원인, 수정, 결과, 후속 판단 | 운영 문제 해결·회고 |

상단의 반복 통계·인벤토리를 없애고, 프로젝트 맥락·역할·첨부 파일 사이드바는 유지했다. 핵심 경험 선택은 가로 탐색으로 바꾸어 세 개의 좁은 열이 생기지 않도록 했다. 기존 판단 요약은 추가 근거로 접어 보존한다.

## 데이터와 안전장치

`jobData.pmWorkProducts`의 일곱 배열은 각 행에 독립된 인용·출처·단계를 갖는다. 초안과 본 분석이 같은 스키마를 사용하며 별도 AI 호출을 추가하지 않는다. 프롬프트가 길어지고 산출물 출력량이 늘 수 있으므로 배열과 필드 길이에 상한을 둔다.

실제 자료에서 확인하지 못한 흐름·규칙은 생성하지 않도록 지시한다. 빈 배열을 활동명에서 합성하지 않는다. 서버는 인용문 존재를 대조하고, 미확인 항목의 개인 책임과 실측 결과를 제거한다. 계획 단계에는 관찰 결과를 남기지 않는다. 이는 의미적 사실 검증이 아니므로 제출 전 사용자 검토가 필요하다.

기존 결과는 자동으로 새 산출물로 승격하지 않는다. `pmWorkProductsVersion`이 없는 결과에는 'PM 산출물 다시 추출'을 제공한다. 원문 자료를 이용한 재분석이 필요하며 실제 고객 자료로 유료 AI를 호출하거나 운영 DB를 변경하지 않았다. 자유 서술 보강은 원본 파일이 없는 경로라 이미 추출한 산출물을 보존한다.

경험 결과·직군 특화 화면·공통 포트폴리오 및 프로젝트 초안 내보내기에 같은 산출물을 연결한다. 인쇄에서는 접힌 원문과 판단 요약도 표시한다. 개발자와 마케터의 별도 추출 동작은 유지한다.
