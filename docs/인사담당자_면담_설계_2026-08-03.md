# 인사담당자 전문가 면담 설계

작성일: 2026-08-03
대상: 채용·인사 실무 경력이 긴 현직/전직 인사담당자 1인
목적: FitPoly 산출물이 **실제 서류 심사에서 통하는지**를 검증하고, 통하지 않는다면 어디를 바꿔야 하는지 확정한다
권장 시간: 90분 (최소 60분)

---

## 0. 이 면담의 목적을 먼저 좁힌다

이 면담은 **제품 피드백을 받는 자리가 아니다.** 전문가에게 "저희 서비스 어떠세요?"라고 물으면 대부분 예의 바른 칭찬이나 일반론이 돌아오고, 그건 이미 우리가 받은 피드백 14건(평균 4.8/5)과 똑같은 성격의 정보다. 그 데이터로는 아무 결정도 못 내린다.

이 면담에서 얻어야 하는 것은 딱 세 가지다.

| # | 얻어야 할 것 | 왜 이 사람에게만 물을 수 있나 |
|---|---|---|
| **A** | 서류 심사가 실제로 굴러가는 방식 — 몇 초, 어떤 순서, 무엇으로 탈락 | 지원자는 결과만 알고 과정을 모른다. 심사자만 안다 |
| **B** | 우리 산출물을 심사자 입장에서 봤을 때의 **실제 반응** | 우리 사용자(지원자)는 "잘 나왔다"고 하지만, 돈을 결정하는 건 통과 여부다 |
| **C** | 우리가 만든 구조(증거·의사결정 기록·자기서사)가 **심사에 쓰이는 정보인지 과잉인지** | 이 판단은 심사 경험이 길어야만 가능하다 |

**A는 사실 확인, B는 실물 관찰, C는 전문가 판단**이다. 세 가지는 묻는 방법이 다르다. 아래 설계는 그걸 분리해 놓았다.

---

## 1. 면담 설계 원칙 5가지

이 원칙을 어기면 90분을 쓰고도 아무것도 못 건진다.

### 원칙 1 — 의견이 아니라 과거 행동을 묻는다

사람은 미래 행동을 잘못 예측한다. 전문가도 마찬가지다.

| ❌ 이렇게 묻지 않는다 | ✅ 이렇게 묻는다 |
|---|---|
| "이런 포트폴리오면 통과될까요?" | "가장 최근에 통과시킨 신입 지원자 서류를 떠올려 주세요. 무엇 때문에 통과시키셨나요?" |
| "증거 자료가 붙어 있으면 좋을까요?" | "지원자가 첨부한 링크나 자료를 실제로 열어보신 적이 있나요? 최근 언제였나요?" |
| "AI로 쓴 자소서 어떻게 보세요?" | "AI로 썼다고 판단한 서류가 있었나요? 무엇을 보고 그렇게 판단하셨나요? 그래서 어떻게 하셨나요?" |

### 원칙 2 — 우리 제품을 최대한 늦게 꺼낸다

제품을 먼저 보여주면 그 뒤 모든 답이 우리 제품을 기준으로 왜곡된다. **Part 1(심사 현실)이 끝나기 전까지 FitPoly라는 이름도 꺼내지 않는다.**

### 원칙 3 — 숫자를 반드시 뽑아낸다

"많이 봐요", "가끔요" 같은 답은 기록해도 쓸 수 없다. 항상 되묻는다.

> "대략 몇 건 중 몇 건 정도일까요?"
> "한 건에 몇 초/몇 분 정도 쓰시나요?"
> "10명 중 몇 명이라고 보면 될까요?"

### 원칙 4 — 반대 증거를 적극적으로 찾는다

우리 가설을 확인해주는 말보다 **깨는 말이 훨씬 가치 있다.** 상대가 우리 방향에 동의하면 한 번 더 압박한다.

> "혹시 그렇지 않은 경우도 있을까요? 어떤 상황에서요?"
> "이 방식이 오히려 방해가 되는 지원자 유형이 있을까요?"

### 원칙 5 — 산출물은 말로 설명하지 말고 보여주고 침묵한다

Part 2가 이 면담의 핵심이다. 우리가 설명을 붙이는 순간 그 사람은 우리 설명을 평가하지, 산출물을 평가하지 않는다. **화면만 띄우고 입을 다문다.**

## 2. 사전 준비 체크리스트

면담 전날까지 끝낸다. 준비가 안 되면 Part 2를 못 하고, 그러면 이 면담은 절반 이하의 가치만 남는다.

### 실물 준비

- [ ] **인쇄물 3종** (화면보다 종이가 낫다 — 심사 현실에 가깝고, 상대가 펜으로 표시할 수 있다)
  - [ ] `A` FitPoly 산출물 PDF — **개발 직군** 1부
  - [ ] `B` FitPoly 산출물 PDF — **비개발 직군**(기획/마케팅) 1부
  - [ ] `C` 대조군 — FitPoly 없이 쓴 평범한 신입 포트폴리오 1부
- [ ] 3종 모두 **같은 가상 인물, 같은 경험**으로 맞춘다. 그래야 형식 차이만 비교된다
- [ ] 파일명·표지에서 FitPoly 브랜드를 **제거**한다 (원칙 2)
- [ ] 공개 링크 버전 1개 (`/p/:id`) — 모바일에서 열어볼 수 있게
- [ ] `/sample` 화면 (산출물 예시) 노트북에 미리 띄워두기

### 기록 준비

- [ ] **녹음 동의**를 사전 메시지로 미리 받아둔다 (당일에 물으면 거절 확률이 올라간다)
- [ ] 기록자 1명 별도 배치 — 진행자가 받아적으면 대화가 끊긴다. 불가능하면 녹음에 전적으로 의존하고 진행에 집중
- [ ] 아래 §9 기록 템플릿 인쇄 또는 화면 분할

### 사전 메시지 예시

> 안녕하세요. 취업 준비생의 경험 정리를 돕는 서비스를 만들고 있는 최형균입니다.
> 제품 자랑을 하려는 자리가 아니라, **채용 서류를 실제로 심사해 오신 관점에서 저희가 뭘 잘못 알고 있는지**를 듣고 싶어 연락드렸습니다.
> 90분 정도 부탁드리며, 준비물은 없습니다. 정확한 기록을 위해 녹음을 남겨도 괜찮을까요? 기록은 내부 제품 개선에만 쓰고 외부 공개하지 않습니다.

## Part 0 — 맥락 확보 (10분)

이 사람의 답이 **어느 범위에서 유효한지** 정하는 구간이다. 대기업 공채 심사자와 스타트업 수시채용 심사자의 답은 완전히 다르고, 둘 다 맞다.

1. 어떤 규모·업종의 회사에서, 몇 년 동안 채용을 담당하셨나요?
2. 직접 서류를 보신 채용은 주로 어느 직군이었나요? 신입과 경력 비중은 어느 정도였나요?
3. 한 번의 공고에 서류가 보통 몇 건 들어왔나요? 그중 몇 명을 면접으로 넘기셨나요?
4. 서류 심사를 혼자 하셨나요, 현업 부서와 나눠 하셨나요? 최종 결정권은 누구에게 있었나요?
5. 채용 시스템(ATS·그리팅·잡다·사람인 등)을 쓰셨나요? 무엇을요?

> 📌 **기록 필수 항목**: 회사 규모 / 담당 직군 / 신입 비중 / 서류 유입량 / 통과율 / ATS 사용 여부
> 이 6개가 있어야 나중에 "이 사람 말은 어디까지 적용되는가"를 판단할 수 있다.

## Part 1 — 심사 현실 재구성 (25분)

**절대 제품을 꺼내지 않는다.** 순수하게 이 사람의 업무를 복원한다.

### 1-A. 한 건을 처리하는 실제 과정

6. 서류 100건이 들어왔다고 하면, 첫 스크리닝에서 한 건에 실제로 몇 초 정도 쓰시나요?
7. 화면에서 **가장 먼저 보시는 순서**를 그대로 말씀해 주세요. 무엇을 보고 그다음 무엇을 보나요?
8. 첫 스크리닝에서 **탈락시키는 이유 상위 3개**는 무엇이었나요? 빈도 순으로요.
9. 반대로 "이건 일단 남겨두자" 하고 표시하게 만드는 신호는 무엇인가요?
10. 100건 중 자기소개서나 포트폴리오 **본문까지 끝까지 읽는 건 몇 건**쯤 되나요?

### 1-B. 포트폴리오의 실제 지위

11. 지원자가 낸 포트폴리오를 **실제로 여시는 비율**은 어느 정도인가요? 직군별로 다른가요?
12. 포트폴리오를 여는 시점은 언제인가요? 서류 심사 때인가요, 면접 직전인가요?
13. 포트폴리오가 **당락을 바꾼 사례**가 기억나시나요? 구체적으로 어떤 경우였나요?
14. 반대로 포트폴리오 때문에 **감점된** 사례가 있었나요?
15. 첨부 링크(노션·깃허브·개인 사이트)를 실제로 클릭해 보시나요? 최근에 클릭하신 게 언제인가요?

> 🎯 **여기서 검증하는 가설**
> 우리는 "포트폴리오가 당락을 가른다"는 전제 위에 제품을 만들었다. **비개발 직군에서 이 전제가 깨지면 23개 직군 전략 전체를 재검토해야 한다.**

### 1-C. 신입·주니어 특수성

16. 신입 지원자 서류에서 **경력자와 다르게** 보시는 게 있나요?
17. 신입 서류는 대부분 비슷비슷할 텐데, 그중에서 차이를 만드는 건 무엇이었나요?
18. 학교 프로젝트·동아리·인턴 중 실제로 가중치를 두시는 게 있나요? 순서를 매겨주신다면요?
19. 신입이 쓴 "성과 수치"(예: 만족도 4.6/5, 이탈률 32% 감소)를 보시면 어떤 생각이 드시나요?

> 🎯 **여기서 검증하는 가설**
> 우리 파이프라인은 **수치화된 성과**를 채우도록 사용자를 계속 압박한다(누락 항목 패널, "수치로 간단히 채우기" 위젯). 심사자가 신입의 자가 보고 수치를 신뢰하지 않는다면, 이 압박은 사용자를 괴롭히기만 하고 통과율은 못 올린다.

### 1-D. 검증과 신뢰

20. 지원자가 쓴 내용을 **사실 확인**하시나요? 한다면 어떤 방법으로요?
21. 과장이나 거짓이라고 판단하신 경우가 있나요? 무엇을 보고 아셨나요?
22. "팀 프로젝트인데 본인이 다 한 것처럼 쓴" 경우는 어떻게 구분하시나요?
23. 지원자가 **본인 기여도를 명시**(예: "백엔드 API 70% 담당")하면 도움이 되나요, 아니면 그것도 못 믿나요?

## Part 2 — 산출물 실물 평가 (25분) ⭐ 핵심

여기가 이 면담의 값이다. **진행 방식이 질문 내용보다 중요하다.**

### 진행 프로토콜

```
1. 인쇄물 C(대조군) → A(개발) → B(비개발) 순으로 한 부씩 건넨다
2. 건네면서 딱 한 문장만 말한다:
   "신입 지원자 서류라고 생각하고, 평소 하시던 대로 봐 주세요.
    보시면서 드는 생각을 소리내어 말씀해 주시면 감사하겠습니다."
3. 그리고 침묵한다. 설명하지 않는다. 질문에 답하지 않는다.
   ("이건 뭔가요?" → "편하신 대로 해석해 주세요")
4. 스톱워치로 각 부에 쓴 시간을 잰다
5. 시선이 멈춘 곳, 넘긴 페이지, 되돌아간 페이지를 기록한다
```

> ⚠️ **가장 흔한 실패**: 상대가 잠깐 침묵할 때 진행자가 불안해서 설명을 시작하는 것. 그 순간 관찰은 끝난다. **10초 침묵을 견딘다.**

### 관찰 기록표 (읽는 동안 진행자가 채운다 — 묻지 않는다)

| 관찰 항목 | C(대조군) | A(개발) | B(비개발) |
|---|---|---|---|
| 총 소요 시간 | | | |
| 가장 오래 머문 지점 | | | |
| 건너뛴 섹션 | | | |
| 되돌아간 지점 | | | |
| 소리내어 읽은 부분 | | | |
| 눈살 찌푸림·헛웃음·"음…" 발생 지점 | | | |
| 자발적으로 던진 질문 | | | |

### 다 본 뒤에 묻는 질문

24. 지금 이 서류, 면접에 부르시겠어요? **그렇다/아니다로 먼저** 답해 주세요.
25. 그렇게 판단하신 결정적 근거는 몇 페이지 어느 부분인가요? 짚어주세요.
26. 읽으시면서 **건너뛴 부분**이 있는데, 왜 건너뛰셨나요?
27. 세 부 중 하나만 통과시켜야 한다면 어느 것인가요? 왜죠?
28. 이 서류에서 **빼도 되는 부분**은 어디인가요? 없으면 없다고 해주세요.
29. 반대로 **여기서 빠져 있어서 아쉬운 정보**는 무엇인가요?
30. 이 서류를 보고 지원자에게 **면접에서 물어보고 싶은 질문**이 생겼나요? 뭐가 궁금해지셨나요?

> 🎯 **28번이 이 면담 전체에서 가장 중요한 질문일 수 있다.**
> 우리는 직군별 특화 섹션을 계속 늘려왔다(개발 임팩트, 린 캔버스, 가설 검증, 자료 판독 근거 장부, 역량·증거 매핑…). **심사자가 "이건 안 봐요"라고 말하는 섹션은 사용자의 시간과 우리 크레딧만 태우고 있는 것이다.**

### 링크 버전 추가 확인

31. (모바일로 공개 링크를 열어 건네며) 지원자가 이런 링크를 이력서에 적어 왔다면 여실 건가요?
32. 여신다면 PC로 여시나요, 모바일로 여시나요? 언제 여시나요?
33. PDF 첨부와 링크 중 어느 쪽이 나으신가요? 이유는요?

> 🎯 우리는 링크 공유 기능을 만들어 뒀지만 **공개 포트폴리오 사용자는 157명 중 9명(5.7%)**뿐이다. 사용자가 안 쓰는 건지, 써도 소용없는 건지 여기서 갈린다.

## Part 3 — 우리 설계 판단 정면 검증 (15분)

이제 제품 이름을 밝히고 **우리가 내린 판단을 하나씩 깨보라고 부탁한다.**

> "지금부터는 저희가 내린 설계 판단들인데요, 이게 틀렸다면 어디가 틀렸는지 말씀해 주시면 가장 도움이 됩니다."

### 가설 H1 — 증거 기반 구조

우리 제품은 주장마다 **증거 자료 상태**(확보됨 / 확인 필요 / 추가 필요)를 붙이고, 증거 없는 경험을 경고한다.

34. 심사자 입장에서 지원자가 증거 상태를 명시하는 게 신뢰를 올리나요, 아니면 "이런 것까지 관리하나" 싶어 어색한가요?
35. 만약 지원자가 "이 수치는 제가 직접 측정한 게 아니라 팀 공유 자료 기준입니다"라고 솔직히 적었다면 어떻게 보시겠어요?

### 가설 H2 — 의사결정 기록

우리는 **"왜 그렇게 판단했는가"**(대안, 근거, 검증, 바뀐 생각)를 뽑아내 넣는다.

36. 신입 서류에서 "판단 근거"까지 읽으시나요? 아니면 신입에게는 과한가요?
37. "생각이 바뀐 순간 / 실수했던 것"을 지원자가 스스로 적는 건 플러스인가요, 마이너스인가요?

> 🎯 우리는 `honestReview.misjudgment`(오판 기록)를 산출물에 넣고 있다. **자기 약점 노출이 신입에게 불리하다면 이건 사용자를 해치는 기능이다.**

### 가설 H3 — AI 생성물

38. 서류를 보고 "AI로 썼구나" 판단하신 적 있나요? 무엇을 보고 아셨나요?
39. AI로 쓴 티가 나면 감점하시나요? 아니면 요즘은 당연하다고 보시나요?
40. AI 도움을 받되 **감점되지 않는 선**은 어디라고 보세요?
41. 저희 산출물(A·B)에서 AI로 만든 느낌이 드는 부분이 있었나요? 어디였나요?

### 가설 H4 — 채용공고 맞춤

우리는 **공고를 붙여넣으면 역량·증거를 매핑**해 주는 기능을 만들었다. 그런데 실제 사용은 **2건**이다.

42. 지원자가 공고 문구에 맞춰 포트폴리오를 고쳐 오는 게 티가 나나요?
43. 티가 난다면 좋게 보시나요, 얄팍해 보이시나요?
44. 공고의 자격요건과 지원자 경험을 1:1로 대응시켜 보여주면 심사에 도움이 되나요?

### 가설 H5 — 자기 서사

우리는 여러 경험을 가로질러 **"나는 어떤 사람인가"**(반복 패턴, 판단 원칙, 성장 궤적)를 만들어준다.

45. 이런 자기 분석이 서류 심사에 쓰이나요? 아니면 면접에서나 의미가 있나요?
46. 신입이 "제 판단 원칙은 ○○입니다"라고 쓰면 설득력 있게 들리나요?

---

## Part 4 — 직군 범위와 유통 (10분)

47. 저희는 현재 23개 직군을 지원합니다. 직군에 따라 **포트폴리오의 의미가 크게 다른** 곳이 있나요? 포트폴리오가 사실상 무의미한 직군은요?
48. 반대로 포트폴리오 없이는 심사가 안 되는 직군은 어디인가요?
49. 회사에서 이런 도구를 **지원자에게 권할** 이유가 있을까요? 아니면 회사 입장에선 상관없는 일인가요?
50. 대학 취업지원팀이나 부트캠프가 이런 걸 도입한다면, 무엇을 근거로 결정할까요?
51. 채용 담당자 쪽에서 돈을 낼 만한 인접 문제가 있을까요? (예: 지원서 사전 정리, 스크리닝 보조)

> 🎯 우리 크레딧 결제는 현재 **수동 계좌이체이고 승인 2건**뿐이다. B2C 지불의사가 약하다면 B2B(학교·부트캠프·채용사) 경로가 실질적 대안인지 여기서 처음 탐색한다.

53. 이 주제로 이야기 나눠보면 좋을 분을 한 분 소개해 주실 수 있을까요? (특히 **현직 심사자 / 다른 직군 / 다른 회사 규모**)

이 목록을 인쇄해서 눈앞에 둔다. 하나라도 하면 그 뒤 답이 오염된다.

## 6. 면담 직후 30분 안에 할 일

기억은 하루면 절반이 날아간다. **당일에 끝낸다.**

1. 녹음과 별개로 **기억나는 인상적 발언 10개**를 먼저 적는다
2. **"놀란 것 3개"**를 적는다 — 예상과 일치한 것은 정보가 적고, 어긋난 것이 정보다
3. 가설 판정표(H1~H5)를 채운다. **불명은 불명으로 남긴다.** 억지로 판정하지 않는다
4. 산출물에서 **"안 본다"고 한 섹션 목록**을 그대로 옮긴다

---

## 7. 판정 기준 — 무엇을 들으면 무엇을 바꾸는가

면담 전에 **미리 정해둔다.** 듣고 나서 정하면 듣고 싶은 대로 해석하게 된다.

| 들은 내용 | 바꿀 것 |
|---|---|
| 비개발 직군에서 포트폴리오를 거의 안 연다 | 23개 직군 → **개발 중심으로 축소**. 비개발은 이력서·자소서 산출물로 전환 |
| 특정 섹션을 "안 본다"고 3개 이상 지목 | 해당 섹션을 **기본 출력에서 제외**, 고급 옵션으로 이동 (사용자 시간·크레딧 절감) |
| 신입 자가보고 수치를 신뢰하지 않는다 | **수치 강요 UX 완화**. 누락 항목 패널의 압박 톤 조정 |
| 오판·약점 기록이 마이너스다 | `honestReview.misjudgment`를 **서류용 산출물에서 제외**하고 면접 준비 자료로만 사용 |
| AI 티가 나면 감점된다 | 문장 생성 축소, **사용자 원문 보존 비중 상향** |
| 공고 맞춤이 실제로 효과 있다 | 사용률 2건은 **발견성 문제** → 공고 입력을 기본 경로로 승격 |
| 공고 맞춤이 얄팍해 보인다 | 해당 기능 **우선순위 하향**, 리소스 회수 |
| 링크보다 PDF를 선호한다 | 링크 공유 기능 투자 중단, **PDF 품질에 집중** |
| B2B(학교·부트캠프) 수요가 있다 | 수동 계좌이체 문제를 **B2B 계약으로 우회** 검토 |

## 8. 이 면담의 한계 (미리 인정하고 시작한다)

- **n=1이다.** 한 사람의 경험은 그 사람의 회사·직군·시기에 갇혀 있다. 여기서 나온 판정은 **가설의 강화/약화**이지 결론이 아니다
- 같은 설계로 **최소 3명**(대기업 공채 / 스타트업 수시 / 현업 면접관)을 만나야 패턴이 보인다
- 심사자의 말과 실제 행동도 어긋날 수 있다. 그래서 **Part 2 관찰**을 넣었다 — 말보다 행동 기록을 더 신뢰한다
- 이 면담은 **"통과되는 서류"**를 검증하지, **"사용자가 돈을 내는가"**를 검증하지 않는다. 후자는 별도 검증이 필요하다
