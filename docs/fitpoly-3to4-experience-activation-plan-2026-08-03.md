# 핏폴리 3~4개 경험 축적·포트폴리오 전환 계획

작성일: 2026-08-03  
목표: 사용자가 첫 경험 하나를 정리한 뒤 이탈하지 않고, 포트폴리오에 필요한 3~4개의 검증된 경험을 모아 지원용 결과물까지 완성하게 만든다.

> 현재 코드와 Firebase 익명 집계를 기준으로 설계했다. 이 문서의 수치는 전체 누적 사용자 상태를 나타내므로, 구현 후에는 가입 코호트와 관찰 기간을 맞춰 다시 측정해야 한다.

## 1. 핵심 결론

핏폴리는 “경험 하나 정리 완료” 화면을 최종 결과처럼 보여주면 안 된다. 그렇다고 3~4개를 모을 때까지 아무 보상도 주지 않으면 첫 경험조차 시작하기 어렵다.

따라서 제품을 두 개의 보상이 이어지는 구조로 바꿔야 한다.

1. **첫 경험의 즉시 보상**: 한 경험이 포트폴리오 카드와 검증된 문장으로 바뀌는 모습을 바로 보여준다.
2. **경험 묶음의 최종 보상**: 서로 다른 강점을 증명하는 3~4개 경험을 모으면 지원 직무에 맞는 포트폴리오 플랜을 자동 구성한다.

핵심 전환은 다음과 같다.

```text
첫 경험 완료
  ↓ 즉시 결과 확인
포트폴리오 준비도 1단계
  ↓ 가장 적합한 다음 경험을 한 개만 추천
두 번째 경험 초안 시작
  ↓ 빈 역량을 기준으로 다음 경험 추천
3개 경험 + 최소 품질 충족
  ↓
포트폴리오 플랜 자동 생성
  ↓ 선택적으로 4번째 보강
지원 회사 맞춤 결과물 생성·내보내기
```

## 2. 현재 데이터가 보여 주는 정확한 병목

### 사용자별 경험 개수

| 보유 경험 수 | 사용자 | 경험 사용자 98명 중 비율 |
|---|---:|---:|
| 정확히 1개 | 73 | 74.5% |
| 정확히 2개 | 11 | 11.2% |
| 정확히 3개 | 3 | 3.1% |
| 4개 이상 | 11 | 11.2% |

누적 전환으로 보면 다음과 같다.

```text
경험 1개 이상  98명  100%
경험 2개 이상  25명   25.5%
경험 3개 이상  14명   14.3%
경험 4개 이상  11명   11.2%
```

- 첫 경험 사용자의 74.5%가 한 개에서 멈춘다.
- 2개까지 간 사용자의 56.0%는 3개까지 간다.
- 3개까지 간 사용자의 78.6%는 4개까지 간다.
- 두 번째 경험까지 만든 25명 중 23명은 첫 경험 후 24시간 안에 만들었고, 25명 전원이 7일 안에 만들었다.
- 첫 경험부터 두 번째 경험까지의 중앙값은 약 0.02일, 약 29분이다.

이 값은 **이메일로 며칠 뒤 되살리는 것보다 첫 경험 완료 직후 같은 세션에서 두 번째 경험을 시작시키는 것이 훨씬 중요하다**는 뜻이다.

### 포트폴리오가 너무 일찍 만들어짐

현재 사용자 상태에서는 경험이 정확히 1개인 사용자 73명 중 49명도 포트폴리오를 생성했다. 포트폴리오 생성 자체는 많지만, 한 경험만 들어간 결과물이 실제 지원용으로 충분한지는 알 수 없다.

현재 상세 경험에서 포트폴리오로 보내는 데이터도 기본적으로 경험 한 개 단위의 `exportConfig`다. 따라서 제품은 사용자가 경험 3~4개를 선별·배치하는 “포트폴리오 플랜”보다, 한 경험을 기존 포트폴리오에 추가하는 편집 작업을 먼저 시킨다.

### 현재 경험 수와 품질을 구분하지 않음

경험 문서 177건 중 176건에 구조화 결과가 있으나, “사용자가 사실을 확인했는가”, “포트폴리오에 쓸 만큼 역할·행동·결과가 채워졌는가”를 나타내는 명시적인 상태가 없다.

따라서 `경험 4개`라는 개수 목표만 만들면 다음 문제가 생긴다.

- 같은 프로젝트를 억지로 네 개로 분리
- 역할이나 결과가 없는 약한 경험을 숫자 채우기로 등록
- AI가 만든 문장을 확인하지 않고 완료 처리
- 실제 강한 프로젝트가 두 개인 경력자를 불필요하게 막음

해결책은 **경험 개수 + 경험 품질 + 역량 커버리지**를 함께 보는 것이다.

## 3. 새 제품 단위: “포트폴리오 경험 묶음”

### 기본 구성

포트폴리오 하나에 다음 역할을 담당하는 경험을 배치한다.

| 슬롯 | 보여 줘야 하는 것 | 예시 |
|---|---|---|
| 대표 성과 | 가장 강한 결과와 직무 적합성 | 전환율 개선, 제품 출시, 모델 성능 개선 |
| 문제 해결 | 어려운 문제를 정의하고 해결한 과정 | 장애 대응, 리서치 기반 개선, 기술 부채 해소 |
| 협업·조율 | 타인과 결과를 만든 방식 | 디자이너·개발자 협업, 이해관계자 설득 |
| 성장·주도성 | 학습, 실패, 오너십, 다음 판단 | 처음 맡은 업무, 실험 실패 후 개선 |

경험 하나가 여러 슬롯을 충족할 수 있다. 기본 완성 기준은 다음처럼 둔다.

- **최소 준비 완료**: 검증된 경험 3개 + 네 슬롯의 커버리지 충족
- **권장 준비 완료**: 검증된 경험 4개 + 지원 직무 핵심 역량 커버리지 충족
- **예외 허용**: 규모가 큰 프로젝트 2개만 있어도 각 프로젝트에 서로 다른 검증된 문제 해결 장면과 결과가 충분하면 사용자가 계속 진행 가능

즉, 3개를 하드 게이트로 막기보다 기본 추천값으로 사용한다.

### 경험 하나의 “포트폴리오 준비 완료” 기준

다음 여섯 항목 중 필수 네 항목을 모두 충족해야 한다.

#### 필수

1. 배경 또는 해결할 문제
2. 본인의 역할과 기여 범위
3. 본인이 실제로 한 행동·판단
4. 결과 또는 배운 점

#### 권장

5. 원문 자료 위치 또는 사용자 사실 확인
6. 수치, 산출물, 링크, 이미지 중 하나 이상의 보강 근거

수치가 없는 경험을 실패 처리해서는 안 된다. 수치 대신 결과, 의사결정 변화, 산출물, 이해관계자 반응, 학습을 사용할 수 있다.

### 경험 상태 모델

```text
captured
  제목이나 자료만 저장
    ↓
extracted
  AI가 구조화 초안 생성
    ↓
needs_confirmation
  역할·결과·근거 확인 필요
    ↓
portfolio_ready
  필수 항목 확인 완료
    ↓
selected_in_plan
  특정 포트폴리오 플랜에 배치
```

현재처럼 `structuredResult`가 존재한다고 완료로 간주하지 않는다.

## 4. 목표 사용자 경험

### 단계 0. 시작 전에 목표만 받기

첫 화면에서 긴 프로필 대신 세 가지만 묻는다.

1. 어떤 직무로 지원하는가? — 건너뛰기 가능
2. 언제까지 포트폴리오가 필요한가?
3. 정리할 자료가 어디에 있는가? — 파일, GitHub, Notion, 직접 대화

이 정보는 다음 경험 추천과 마감 알림에만 사용한다. 학력·수상·상세 프로필은 포트폴리오 생성 직전에 필요한 것만 받는다.

권장 문구:

> 먼저 경험 하나를 포트폴리오 카드로 바꿔볼게요. 첫 결과는 약 5~10분 안에 확인할 수 있어요.

### 단계 1. 첫 경험을 완성해 즉시 보상

첫 경험 분석이 끝나면 긴 상세 편집 화면에 그대로 남기지 말고 별도의 완료 전환 화면을 보여 준다.

```text
첫 경험이 준비됐어요

[포트폴리오 카드 미리보기]
문제: 사용자가 …
내 역할: …
행동: …
결과: …

포트폴리오 준비도 1 / 3
이 경험은 ‘문제 해결’과 ‘대표 성과’를 채웠어요.

[다음 경험 3분 초안 만들기]  ← 기본 CTA
[현재 포트폴리오 뼈대 보기]   ← 보조 CTA
```

사용자는 첫 경험만으로도 결과를 얻었다고 느끼지만, 동시에 무엇이 남았는지 이해한다.

### 단계 2. 다음 경험을 사용자가 떠올리게 하지 않기

“새 경험 추가”라는 빈 버튼은 인지 부담이 크다. 현재 경험과 목표 직무를 바탕으로 **다음으로 정리할 경험 한 개만** 추천한다.

추천 규칙의 우선순위:

1. 현재 경험 묶음에서 비어 있는 슬롯
2. 지원 직무 핵심 역량 중 근거가 없는 역량
3. 기존 업로드 자료에서 이미 감지된 다른 프로젝트
4. 최근 경험
5. 사용자가 설명하기 쉬운 경험

예시:

> 지금 경험은 실행력은 잘 보이지만 협업 근거가 부족해요.  
> 디자이너나 팀원과 의견을 조율했던 프로젝트가 있나요?

선택지는 두 개만 준다.

- `네, 이 경험으로 시작할게요`
- `다른 경험 추천받기`

### 단계 3. “3분 초안”으로 두 번째 경험 시작 장벽 낮추기

두 번째 경험부터 첫 경험과 같은 전체 인터뷰를 반복하면 피로가 커진다. 먼저 다음 네 질문만으로 초안을 저장한다.

1. 경험 제목 또는 기억나는 한 줄
2. 당시 해결하려던 문제
3. 내가 한 가장 중요한 행동
4. 결과 또는 배운 점

자료가 있다면 바로 첨부한다. 초안을 저장한 순간 `captured` 상태가 되고, 사용자는 나중에 확인을 이어갈 수 있다.

핵심은 두 번째 경험을 완전히 끝내게 하는 것보다 **첫 경험 완료 세션 안에 두 번째 경험의 소유권을 만들게 하는 것**이다.

### 단계 4. 한 자료에서 여러 경험 후보 찾기

파일 가져오기가 741건 중 650건으로 압도적으로 많다. 사용자가 이력서·회고·Notion 문서 하나를 올렸다면 추가 파일을 계속 요구하지 말고 문서 안의 다른 경험 후보를 먼저 찾아야 한다.

```text
이 자료에서 3개의 경험 후보를 찾았어요

[체크] 결제 전환 개선 프로젝트
[체크] 디자인 시스템 협업
[   ] 동아리 운영 경험

[선택한 2개를 초안으로 저장]
```

후보 탐지는 전체 AI 분석보다 저렴한 1차 분리 작업으로 한다. 사용자가 선택한 후보만 깊게 분석한다.

후보에는 다음만 저장한다.

- 임시 제목
- 기간 힌트
- 출처 문서와 근거 위치
- 예상 슬롯과 역량
- `suggested/accepted/dismissed/converted` 상태

같은 프로젝트의 세부 업무를 별도 경험으로 잘못 나누지 않도록 “같은 프로젝트로 합치기” 기능이 필요하다.

### 단계 5. 경험 허브를 목록에서 준비 보드로 바꾸기

현재 상단은 경험 개수와 타임라인·목록·대시보드·프로필 탭을 먼저 보여 준다. 경험이 3개 미만인 사용자에게는 관리 도구보다 다음 행동이 중요하다.

경험 0~2개 사용자의 기본 화면:

```text
지원용 포트폴리오 준비도 42%

● 대표 성과        완료
● 문제 해결        완료
○ 협업·조율        다음 추천
○ 성장·주도성      아직 근거 부족

현재 1개의 검증된 경험이 있어요.
다음 추천: 팀원과 의견을 조율한 프로젝트

[다음 경험 초안 만들기]
[업로드 자료의 경험 후보 2개 보기]
```

타임라인·목록·대시보드·프로필은 “내 경험 관리” 아래의 보조 탭으로 유지한다.

경험 3개 이상 사용자의 기본 화면:

```text
포트폴리오 플랜을 만들 준비가 됐어요

대표 성과      A 프로젝트
문제 해결      B 프로젝트
협업·조율      C 프로젝트
성장·주도성    A 또는 C 프로젝트

[포트폴리오 플랜 만들기]
[4번째 경험으로 보강하기]
```

### 단계 6. 포트폴리오를 먼저 만들지 말고 “플랜”을 만든다

현재는 템플릿 선택이나 빈 포트폴리오 생성으로 바로 갈 수 있다. 이를 콘텐츠 플랜이 먼저인 흐름으로 바꾼다.

```text
지원 목표 선택
  ↓
경험 3~4개 자동 추천·사용자 확정
  ↓
경험별 역할 결정
  대표 / 문제 해결 / 협업 / 보강
  ↓
스토리 순서와 누락 근거 확인
  ↓
추천 템플릿 1개
  ↓
편집·내보내기
```

포트폴리오 플랜 화면에는 다음을 보여 준다.

- 지원 회사·직무 또는 일반 목표
- 선택 경험 3~4개
- 경험별 한 줄 역할
- 경험 사이 중복 문장·역량
- 부족한 근거
- 추천 순서와 이유
- 예상 페이지·섹션 구성

사용자가 직접 경험을 교체하고 순서를 바꿀 수 있어야 한다.

### 단계 7. 1~2개 경험 사용자에게도 미리보기를 허용

3개 전까지 결과를 숨기면 이탈한다. 포트폴리오 뼈대는 첫 경험부터 보여 주되 상태를 명확히 표시한다.

- 1개: “첫 프로젝트 카드 미리보기”
- 2개: “포트폴리오 뼈대”와 비어 있는 역량 슬롯
- 3개: “지원용 초안 준비 완료”
- 4개: “선택·압축 단계”

내보내기를 하드 차단하지 않는다. 다만 1~2개일 때는 다음처럼 안내한다.

> 지금도 초안으로 내보낼 수 있어요. 지원용 완성도를 높이려면 협업 경험 한 개를 더 추가하는 것을 권장해요.

### 단계 8. 4개 이후에는 더 모으게 하지 않기

목적은 경험 수집 중독이 아니라 지원이다. 4개의 강한 경험이 모이면 기본 CTA를 `새 경험 추가`에서 `지원 회사 연결`로 바꾼다.

5개 이상일 때는 모든 경험을 포트폴리오에 넣지 말고 공고에 가장 맞는 3~4개를 추천한다.

## 5. 이탈 후 복귀 루프

### 우선순위 1: 같은 세션

현재 두 번째 경험까지 간 사용자는 거의 모두 첫날 안에 움직였다. 따라서 다음 기능은 이메일보다 먼저 구현한다.

- 첫 경험 저장 후 전체 화면 전환 CTA
- 이전 자료에서 찾은 다음 후보 자동 제시
- 두 번째 경험을 3분 초안으로 저장
- 새로고침·창 닫기 후 같은 단계 복구
- 상세 결과 화면의 기본 CTA를 `경험 목록`이 아니라 `다음 경험 추가`로 변경

### 우선순위 2: 저장된 후보를 이용한 복귀

막연한 “다시 와서 포트폴리오를 완성하세요” 메시지는 보내지 않는다. 사용자가 저장한 후보나 부족 슬롯이 있을 때만 구체적으로 알린다.

#### D+1

> 어제 정리한 ‘결제 전환 개선’ 경험은 저장돼 있어요.  
> 협업 경험 한 개만 더 정리하면 포트폴리오 뼈대가 완성됩니다. 이어서 약 5분 걸려요.

#### D+3

> 업로드한 자료에서 ‘디자인 시스템 협업’ 후보를 찾았어요. 확인만 하면 두 번째 경험으로 추가할 수 있어요.

#### D+7

마지막 1회만 보낸다. 지원 마감일을 입력한 사용자라면 마감과 남은 작업을 연결한다. 후보가 없거나 알림에 동의하지 않은 사용자에게는 보내지 않는다.

### 복귀 링크

모든 메시지는 일반 홈이 아니라 다음 작업으로 바로 연결한다.

```text
/app/experience/candidate/{candidateId}
/app/experience/{experienceId}/confirm
/app/portfolio-plan/{planId}
```

### 사용하지 않을 장치

- 의미 없는 출석 스트릭
- 3~4개를 채우지 않으면 이전 결과를 못 보게 하는 잠금
- 가짜 긴급성이나 반복 팝업
- 근거 없는 “완성도 90%” 점수
- 사용자 동의 없는 다량 이메일

## 6. 크레딧과 가격도 3~4개 구조에 맞춰야 함

경험 한 개마다 별도 결제를 요구하면서 3~4개를 모으라고 하면 제품 요구와 가격 구조가 충돌한다.

권장 구조:

- 후보 탐지와 3분 초안 저장: 무료
- 첫 경험 구조화: 체험에 포함
- 온보딩용 경험 묶음: 3개 또는 4개를 하나의 “포트폴리오 스타터”로 표시
- 사용자에게는 크레딧보다 “경험 3개 정리 + 포트폴리오 플랜 1개”처럼 결과 단위를 표시
- AI 실행 전에 예상 비용과 남은 묶음 수 표시
- 실패한 분석은 자동 복구 또는 자동 환불

가격 실험은 두 번째 경험 전환 경로가 안정된 뒤 진행한다. 현재는 결제 최적화보다 첫 경험에서 두 번째 경험으로 넘어가는 장벽 제거가 먼저다.

## 7. 데이터 모델 변경안

### Experience 추가 필드

```js
{

  readiness: {
    context: true,
    role: true,
```

```js
{
  userId,
  sourceArtifactId,
  title,
  periodHint,
  evidenceRefs: [],
  suggestedRoles: ['collaboration'],
  suggestedCompetencies: [],
  status: 'suggested' | 'accepted' | 'dismissed' | 'converted',
  convertedExperienceId: null,
  createdAt,
  updatedAt
}
```

### PortfolioPlan

```js
{
  userId,
  targetJobId: null,
  targetRole,
  deadline,
  desiredExperienceCount: 3,
  selectedExperienceIds: [],
  slots: [
    { role: 'flagship', experienceId, status: 'covered' },
    { role: 'problem_solving', experienceId, status: 'covered' },
    { role: 'collaboration', experienceId: null, status: 'missing' },
    { role: 'growth', experienceId, status: 'covered' }
  ],
  missingCompetencies: [],
  readinessStatus: 'collecting' | 'ready' | 'strong',
  createdAt,
  updatedAt
}
```

### 기존 사용자 마이그레이션

- 기존 `structuredResult`에서 필수 필드 존재 여부를 계산해 `readiness` 초안을 채운다.
- 자동으로 `evidenceConfirmed: true`로 만들지 않는다.
- 기존 포트폴리오의 경험 ID를 읽어 플랜 초안을 만들되 사용자 확인을 받는다.
- 경험이 1개인 기존 사용자는 로그인 시 바로 다음 경험 추천 보드로 보낸다.

## 9. KPI와 목표

### 핵심 KPI

**첫 경험 완료 사용자 중 7일 안에 포트폴리오 준비 경험 묶음을 만든 비율**

분모: 첫 번째 `experience_portfolio_ready`를 완료한 사용자  
분자: 7일 안에 `experience_bundle_ready`를 완료한 사용자

기본 조건은 검증된 경험 3개와 슬롯 커버리지다. 단순 문서 3개 생성은 포함하지 않는다.

### 보조 KPI

| 지표 | 목적 |
|---|---|
| E1→E2 시작률, 같은 세션 | 가장 큰 병목 측정 |
| E1→E2 준비 완료율, 24시간 | 첫날 모멘텀 |
| E2→E3 준비 완료율, 7일 | 묶음 완성 |
| 후보 탐지→수락 | 자동 후보 품질 |
| 수락→준비 완료 | 초안 후 편집 부담 |
| 묶음 준비→플랜 생성 | 콘텐츠에서 계획 전환 |
| 플랜 생성→내보내기 성공 | 실제 결과물 완성 |
| 경험당 확인·수정 시간 | 피로도 |
| 근거 미확인 주장률 | 사실성 |
| 알림→작업 복귀율 | 복귀 루프 효율 |

### 8주 초기 목표

아래는 시장 벤치마크가 아니라 내부 개선 목표다.

- E1→E2 24시간 준비 완료율: 현재 누적 상태 기준 약 23.5%에서 35% 이상
- E1→3개 준비 묶음 7일 전환: 성숙 코호트 기준선을 새로 산출한 뒤 1.7배
- 첫 경험 완료 화면→두 번째 경험 시작: 45% 이상
- 저장된 후보 수락률: 50% 이상
- 준비 묶음→포트폴리오 플랜 생성: 60% 이상
- 플랜 생성→내보내기 성공: 50% 이상
- 내보내기 성공률: 99% 이상

최근 가입자는 아직 7일 관찰이 끝나지 않았을 수 있으므로 미성숙 코호트를 분모에 넣지 않는다.

## 10. 실험 계획

사용자 수가 작으므로 대규모 동시 A/B보다 순차 배포와 인터뷰를 함께 사용한다.

### 실험 1. 완료 화면 CTA

- 기존: 저장 후 상세 화면에 남음
- 변경: 카드 미리보기 + 준비도 + 다음 경험 추천
- 성공: 같은 세션 `next_experience_started`
- 안전: 첫 경험 저장 실패, 완료 화면 이탈

### 실험 2. 빈 입력과 구체 추천

- A: `+ 새 경험 추가`
- B: `협업 경험을 추가해 포트폴리오 뼈대 완성하기`
- 성공: E1→E2 시작과 완료

### 실험 3. 후보 자동 탐지

- A: 새 자료 업로드 요청
- B: 기존 자료에서 찾은 후보 2~3개 제시
- 성공: 후보 수락→준비 완료
- 안전: 잘못 분리·중복된 후보 비율

### 실험 4. 개수 진행률과 커버리지 진행률

- A: 경험 1/3
- B: 대표 성과 완료, 협업 부족 등 슬롯 기반 안내
- 성공: 다음 경험 시작, 인터뷰상 이해도
- 주의: 초기에는 둘을 함께 보여 준 뒤 사용자 인터뷰로 단순화 가능

### 실험 5. 포트폴리오 조기 미리보기

- A: 3개 전까지 포트폴리오 CTA 없음
- B: 첫 경험부터 뼈대 미리보기 허용
- 성공: E1→E2 및 묶음 완성
- 안전: 1개 상태의 조기 내보내기와 실망 문의

### 실험 6. 알림

- A: 일반 복귀 메시지
- B: 저장된 후보와 부족 슬롯이 포함된 딥링크
- 성공: 알림 후 24시간 내 `experience_portfolio_ready`
- 안전: 수신 거부, 스팸 신고

각 실험은 숫자와 함께 이탈 사용자 3명, 완주 사용자 2명의 인터뷰를 본다.

## 11. 8주 구현 순서

### 1주차 — 상태와 측정 기반

#### 작업

- `lifecycleStatus`, `readiness` 스키마 추가
- 기존 경험 준비도 백필 스크립트
- E1/E2/E3/E4 순서형 퍼널 사건 구현
- 경험 수가 아니라 `portfolio_ready` 개수를 계산하는 공통 selector 작성
- 가입 코호트와 7일 관찰 완료 여부를 반영한 대시보드

#### 완료 조건

- 특정 사용자의 원문을 보지 않고도 어느 단계에서 멈췄는지 파악 가능
- 기존 경험을 삭제하거나 자동 확인 처리하지 않고 마이그레이션 완료

### 2주차 — 첫 경험 완료 전환 화면

#### 작업

- 첫 경험 저장 후 전용 완료 화면
- 포트폴리오 카드 미리보기
- 개수 + 슬롯 기반 준비도
- 가장 부족한 경험 한 개 추천
- `다음 경험 3분 초안` 기본 CTA
- 창을 닫아도 다음 작업 상태 복구

#### 완료 조건

- 첫 경험 완료 후 사용자가 갈 곳이 경험 목록 하나뿐인 상태 제거
- 완료 화면→두 번째 경험 시작 측정 가능

### 3주차 — 빠른 캡처와 확인

#### 작업

- 네 질문 기반 빠른 초안
- `captured → extracted → needs_confirmation → portfolio_ready` UI
- 필수 항목 체크와 원문 근거 확인
- 수치가 없어도 결과·학습으로 완료 가능
- 동일 프로젝트 병합

#### 완료 조건

- 두 번째 경험 시작에 AI 전체 분석을 필수로 요구하지 않음
- 사용자가 3분 안에 두 번째 초안을 저장 가능

### 4주차 — 자료 속 경험 후보함

#### 작업

- 한 파일에서 여러 프로젝트·경험 후보 탐지
- 후보 선택, 무시, 병합, 초안 전환
- 중복 후보 감지
- 선택한 후보만 깊은 분석 실행

#### 완료 조건

- 기존 업로드 자료가 있는 사용자가 추가 파일 없이 두 번째 경험을 시작 가능
- 후보 오탐과 중복률 측정 가능

### 5주차 — 경험 허브 준비 보드

#### 작업

- 0~2개 사용자 기본 화면을 준비도·다음 행동 중심으로 변경
- 3개 이상 사용자에게 포트폴리오 플랜 CTA
- 타임라인·목록·대시보드는 보조 관리 탭으로 이동
- 4개 이상이면 새 경험보다 지원 회사 연결을 기본 CTA로 전환

#### 완료 조건

- 모든 상태에서 기본 CTA가 하나이고 다음 행동이 구체적임
- 사용자는 무엇이 부족한지 한 화면에서 이해

### 6주차 — 다중 경험 포트폴리오 플랜

#### 작업

- `PortfolioPlan` 생성·저장
- 경험 3~4개 자동 추천과 교체·정렬
- 경험별 대표 역할 표시
- 공고 연결 시 요구 역량 커버리지 계산
- 중복 문장·부족 근거 표시
- 템플릿 선택 전 콘텐츠 구조 확정

#### 완료 조건

- 경험 한 개씩 포트폴리오에 수동 추가하지 않고 묶음으로 생성 가능
- 포트폴리오에 포함된 경험 ID와 순서가 명확히 저장됨

### 7주차 — 복귀와 가격 정렬

#### 작업

- 저장 후보가 있는 사용자만 D+1/D+3/D+7 알림
- 작업 단위 딥링크
- 마감일 기반 남은 작업 안내
- 온보딩 3~4개 경험 묶음의 크레딧 표시
- 실패 자동 환불·재시도

#### 완료 조건

- 메시지 클릭 후 홈이 아니라 미완료 작업으로 복귀
- 알림별 수신·열람·재개·완료 측정

### 8주차 — 안정화와 판정

#### 작업

- 직무·자료 유형별 퍼널 비교
- 상위 이탈 5개 원인 인터뷰·로그 대조
- 후보 품질·AI 비용·편집 시간 검토
- 포트폴리오 플랜→내보내기 종단 테스트
- 다음 8주 확대 또는 중단 결정

#### 판정

- E1→E2가 개선되지 않으면 알림 확대가 아니라 첫 완료 화면과 두 번째 초안 마찰을 다시 수정
- E1→E2는 개선되지만 E2→E3가 막히면 추천 슬롯과 후보 품질 수정
- 3개 묶음은 만들어지지만 플랜 생성이 낮으면 포트폴리오 미리보기 가치와 공고 연결을 수정
- 플랜은 만들지만 내보내지 않으면 편집기·템플릿·출력 안정성이 최우선

## 13. 예외 상황 처리

### 정리할 경험이 정말 1~2개뿐인 사용자

수업, 동아리, 아르바이트, 개인 학습, 실패한 실험도 사실 근거가 있다면 후보로 안내한다. 그래도 없다면 억지로 만들지 않고 2개 프로젝트형 포트폴리오를 허용한다.

### 하나의 큰 프로젝트 안에 여러 문제 해결 장면이 있는 사용자

상위 경험 수는 한 개로 유지하되 프로젝트 안에 핵심 장면을 2~3개 둔다. 포트폴리오 커버리지는 채울 수 있지만 “경험 3개” 숫자를 거짓으로 늘리지 않는다.

### 경험이 5개 이상인 사용자

추가 수집보다 지원 공고에 맞는 3~4개 선택과 중복 제거를 권장한다.

### 이미 한 경험으로 포트폴리오를 만든 사용자

기존 결과를 삭제하거나 새로 만들게 하지 않는다. 플랜을 만든 뒤 “기존 포트폴리오에 나머지 경험 추가”로 갱신한다.

### 자료가 여러 개인데 같은 프로젝트인 경우

파일 단위가 아니라 프로젝트 단위로 묶는다. 한 경험에 여러 `sourceArtifactIds`를 연결한다.

### 직무가 정해지지 않은 사용자

대표 성과·문제 해결·협업·성장이라는 공통 슬롯으로 시작하고, 직무가 정해지면 역량 커버리지만 다시 계산한다.

## 14. 최종 우선순위

가장 먼저 바꿔야 할 순서는 명확하다.

1. 첫 경험 완료를 최종 화면이 아닌 다음 경험 전환 화면으로 만든다.
2. “새 경험 추가” 대신 부족한 포트폴리오 역할에 맞는 경험 한 개를 추천한다.
3. 두 번째 경험을 네 질문으로 같은 세션에 저장하게 한다.
4. 기존 업로드 자료에서 다른 경험 후보를 자동으로 찾아 준다.
5. 3~4개의 경험을 한 번에 선별·배치하는 포트폴리오 플랜을 만든다.
6. 경험 개수, 검증 상태, 역량 커버리지를 모두 반영해 준비도를 계산한다.
7. 이후에만 알림·가격·템플릿을 최적화한다.

현재 데이터에서는 첫 경험 이후 며칠 뒤 돌아오기를 기대하기 어렵다. 제품이 승부해야 하는 시간은 **첫 경험을 완성한 뒤의 약 30분**이다. 이 시간 안에 사용자가 두 번째 경험 초안을 소유하게 만들면, 3~4개 경험 묶음까지 갈 가능성이 크게 높아진다.
