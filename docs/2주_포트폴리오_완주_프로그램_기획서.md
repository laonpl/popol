## 0. 왜 이 프로그램을 하는가

### 우리가 가진 문제 (감사 데이터 기준)

| 사실 | 값 | 의미 |
|---|---:|---|
| 첫 경험을 만든 98명 중 24시간 내 생성 | **83명** | 첫 세션이 사실상 전부다 |
| 포트폴리오 보유자 중 경험 데이터 없음 | **56.1%** | 빈 껍데기를 만들고 떠난다 |
| 채용공고 매칭 문서 | **2건** | 핵심 재사용 루프가 안 돈다 |
| 공개 포트폴리오 사용자 | 157명 중 **9명** | 결과물을 실제로 안 쓴다 |

**진단: 우리 제품은 "한 번 써보고 떠나는" 도구다.** 기능이 부족해서가 아니라, 사용자가 **끝까지 갈 이유와 리듬이 없어서**다.

### 이 프로그램의 정의

> **혼자서는 안 끝나는 일을, 마감·동료·피드백을 붙여서 끝나게 만드는 장치.**

제품 기능을 더 만드는 대신, **완주를 강제하는 운영 레이어**를 씌운다. 이건 마케팅 이벤트가 아니라 **제품 가설 검증 장치**다.

### 이 프로그램으로 검증할 것

| # | 가설 | 판정 기준 |
|---|---|---|
| **G1** | 마감과 동료가 붙으면 완주한다 | 완주율 ≥ 60% |
| **G2** | 완주한 사람은 결과물을 **실제로 쓴다** | 완주자의 ≥ 50%가 실제 지원에 사용 |
| **G3** | 완주 경험이 **재방문**을 만든다 | 종료 4주 후 재방문 ≥ 40% |
| **G4** | 이 경험에 **돈을 낼 의사**가 있다 | 2기 유료 전환 의사 ≥ 30% |
| **G5** | 제품의 어느 단계에서 막히는지 **눈으로 본다** | 단계별 이탈 지점 특정 |

> 📌 **G5가 사실상 가장 큰 수확이다.** 지금 우리는 사건 로깅이 없어 어디서 막히는지 모른다. 14일 동안 30명을 **직접 관찰**하면 로깅 없이도 병목이 보인다.

## 1. 프로그램 개요

| 항목 | 내용 |
|---|---|
| **이름** | (가칭) **2주 포트폴리오 완주단** |
| **한 줄 약속** | "2주 뒤, 실제로 지원서에 넣을 수 있는 포트폴리오 1개를 갖고 나갑니다" |
| **정원** | **1기 20~30명** (운영 감당 한계. 첫 기수는 25명 권장) |
| **기간** | 14일 (월 시작 → 2주 뒤 금 종료) |
| **참가비** | **1기 무료** + 보증금 방식 (§7 참고) |
| **투입 시간** | 참가자 기준 **하루 30~40분**, 총 8시간 내외 |
| **최종 산출물** | 포트폴리오 1부(PDF) + 이력서 1부 + 공개 링크 1개 |

### 완주의 정의 (명확히 못 박는다)

> **"4개 슬롯이 모두 채워진 포트폴리오를 PDF로 내보내고, 공개 링크를 생성한 상태"**

애매하면 완주율을 못 센다. 위 조건을 **하나라도 못 채우면 미완주**로 집계한다.

## 2. 커리큘럼 뼈대 — 제품의 4개 슬롯을 그대로 쓴다

우리 제품은 이미 포트폴리오를 4개 슬롯으로 정의하고 있다 ([`experienceReadiness.js`](../frontend/src/utils/experienceReadiness.js)).

| 슬롯 | 라벨 | 정의 |
|---|---|---|
| `flagship` | **대표 성과** | 가장 강한 결과와 직무 적합성을 보여주는 경험 |
| `problem_solving` | **문제 해결** | 문제를 정의하고 대안을 선택해 해결한 경험 |
| `collaboration` | **협업·조율** | 팀원이나 이해관계자와 결과를 만든 경험 |
| `growth` | **성장·주도성** | 학습, 실패, 오너십 또는 다음 판단을 보여주는 경험 |

**커리큘럼을 새로 발명하지 않는다.** 제품이 이미 요구하는 4칸을 2주에 걸쳐 하나씩 채우게 만든다.

> 💡 이렇게 하면 프로그램 진행률 = 제품의 `PortfolioReadinessBoard` 진행률이 **자동으로 일치**한다. 별도 진도 관리 도구가 필요 없다.

## 4. 이탈 방지 장치

2주 프로그램의 최대 적은 **D3~D6 구간의 조용한 이탈**이다. 아래를 미리 심어둔다.

| 장치 | 내용 | 근거 |
|---|---|---|
| **D1 즉시 성공** | 오리엔테이션 **안에서** 경험 1개를 끝까지 만들어본다 | 첫 세션이 전부라는 데이터. 집에 보내면 안 돌아온다 |
| **매일 인증** | 카톡/디스코드 채널에 스크린샷 1장 | 공개 약속이 완주율을 올린다 |
| **짝 배정** | D1에 2인 1조 고정. D7·D12 상호 리뷰 | 혼자면 포기하고 짝이 있으면 미안해서 한다 |
| **48시간 규칙** | 2일 연속 미인증 시 **운영자가 개별 연락** | 조용한 이탈을 조기에 잡는다 |
| **보증금 환급** | 완주 시 100% 환급 (§7) | 무료는 이탈률이 가장 높다 |
| **진도 자동 표시** | `PortfolioReadinessBoard`의 슬롯 진행률을 그대로 사용 | 별도 도구 없이 진도가 보인다 |
| **막힘 즉시 대응** | 채널 질문 **4시간 내** 응답 SLA | 막힌 채로 하루 지나면 그대로 이탈 |

### 이탈 예상 지점과 대응 (미리 준비)

| 예상 지점 | 원인 가설 | 대응 |
|---|---|---|
| D2 → D3 | "쓸 만한 경험이 없다"는 자기 검열 | D2를 **제목만 10개**로 설계 — 판단 금지, 나열만 |
| D4 | 증거 자료가 실제로 없음 | "증거 없음"도 정상이라고 명시. 확보율 50%면 통과 |
| D5~D6 | 반복 작업 지루함 | D5에 짝과 30분 통화 과제 배치 |
| D11 | 편집기가 무겁고 어려움 | **D11은 실시간 지원 시간 2시간 개설** (편집기 11.2MB 청크 이슈 있음) |
| D13 | 내보내기 실패 | 운영자가 **사전에 전원 계정으로 테스트** |

## 5. 참가자 선발

### 모집 대상

**1순위 — 지금 실제로 지원 중인 사람** (마감이 있는 사람이 완주한다)

| 조건 | 기준 |
|---|---|
| 필수 | 향후 3개월 내 실제 지원 계획이 있음 |
| 필수 | 2주간 하루 30분 확보 가능 |
| 필수 | 정리할 경험 3개 이상 보유 (완성도 무관) |
| 우대 | 개발·기획·디자인·마케팅 직군 |
| 제외 | "그냥 궁금해서" 지원자 → **완주율을 깎는다** |

### 모집 신청서 (5문항)

1. 어떤 직군에 지원하실 계획인가요?
2. 가장 가까운 지원 마감일이 언제인가요? (없으면 "없음")
3. 지금 포트폴리오가 있나요? 있다면 어떤 형태인가요?
4. 정리하고 싶은 경험을 3개만 적어주세요. (한 줄씩)
5. 2주간 하루 30분을 확보할 수 있나요? 어려운 요일이 있다면 적어주세요.

> 🎯 **4번이 선발 기준의 핵심이다.** 3개를 못 적는 사람은 2주 안에 4슬롯을 못 채운다. 다음 기수로 안내한다.

### 직군 구성 (의도적으로 섞는다)

| 직군 | 목표 인원 | 이유 |
|---|---:|---|
| 개발 | 8~10 | 포트폴리오 문화가 확립된 대조군 |
| 기획·PM | 5~7 | 산출물 검증이 가장 필요한 군 |
| 디자인 | 4~5 | 시각 산출물 요구가 다름 |
| 마케팅 | 4~5 | 수치 중심 산출물 검증 |

> 한 직군만 뽑으면 "이 직군에선 되더라"만 알게 된다. **직군별 차이를 보는 게 목적**이다.

## 6. 운영 리소스

### 인력

| 역할 | 투입 | 담당 |
|---|---|---|
| **운영 총괄** | 1명 · 일 2시간 | 실시간 세션, 이탈 관리, 개별 연락 |
| **기술 지원** | 1명 · 대기 | 채널 질문 대응, 오류 즉시 수정 |
| **관찰 기록** | 1명 (겸임 가능) | 막힘 지점 기록 → G5 검증 |

> 25명 기준 **최소 2명**이 필요하다. 1명으로는 D7·D10 실시간 세션에서 개별 화면 리뷰가 불가능하다.

### 크레딧 비용 산정

현재 신규 가입 시 **1,000 크레딧** 자동 지급 ([`billingService.js`](../backend/src/services/billingService.js)).

| 항목 | 값 |
|---|---:|
| 참가자 1인 필요 크레딧 (추정) | 경험 4개 × AI 정리 + 포트폴리오 조립 + 내보내기 3종 |
| 신규 지급분 | 1,000 C |
| 피드백 보상 | +300 C |
| **부족 시 추가 지급 필요량 (추정)** | **1인당 1,000~2,000 C** |
| 25명 기준 추가 지급 | 25,000~50,000 C |
| 원가 환산 (standard 5,000C = 12,000원 기준) | **약 6~12만 원** |

> ⚠️ **크레딧 소모는 토큰 기반이라 정확한 예측이 불가능하다.** D1~D3에 참가자 3명의 실제 소모량을 측정해 **D4에 전원 지급량을 확정**한다. 프로그램 도중 크레딧이 떨어지면 그 사람은 그대로 이탈한다.

### 사전 준비 체크리스트 (D-7까지)

- [ ] 참가자 전원 계정에 **크레딧 선지급** (최소 3,000 C)
- [ ] 운영 채널 개설 (카톡 오픈채팅 또는 디스코드)
- [ ] D1~D14 과제 안내문 14개 **미리 작성** (당일 작성하면 반드시 밀린다)
- [ ] 내보내기 3종(PDF·링크·이력서) **운영자 계정으로 종단 테스트**
- [ ] 짝 배정표 작성 (직군 교차 배정)
- [ ] 실시간 세션 4회 일정 확정 + 캘린더 초대 발송
- [ ] 완주 인증서 디자인
- [ ] 관찰 기록 템플릿 준비 (§9)

## 7. 참가비 구조

### 1기 권장안 — 보증금 환급제

| 구분 | 금액 | 처리 |
|---|---:|---|
| 신청 시 보증금 | **20,000원** | 선입금 |
| 완주 시 | **전액 환급** | 실질 무료 |
| 미완주 시 | 미환급 | 운영비 충당 |

**왜 무료가 아닌가**

- 완전 무료는 **신청은 많고 완주는 적다.** 완주율(G1)을 검증하려는데 노쇼가 섞이면 데이터가 오염된다
- 보증금은 **"진짜 할 사람"만 남기는 필터**다
- 유료화 의사(G4)를 **간접 관찰**할 수 있다 — 환급받고도 2기에 돈 내겠다는 사람이 진짜 수요다

> ⚠️ **결제 인프라 주의**: 현재 결제는 **수동 계좌이체 + 관리자 승인**이고 자동 결제(`creditOrders`)는 paid 0건이다. 보증금은 **제품 결제 시스템을 쓰지 말고** 별도 계좌로 받는다. 프로그램 운영 중 결제 버그가 터지면 프로그램 전체가 흔들린다.

### 2기 이후 (1기 결과에 따라)

| 조건 | 가격 정책 |
|---|---|
| 완주율 ≥ 60% & 유료 의사 ≥ 30% | 유료 전환 (5~9만 원 검토) |
| 완주율 ≥ 60% & 유료 의사 < 30% | 무료 유지 + B2B(학교·부트캠프) 전환 검토 |
| 완주율 < 60% | **프로그램 중단**, 제품 문제부터 해결 |

| 가설 | 지표 | 목표 | 측정 방법 |
|---|---|---:|---|
| G1 완주 | 완주자 ÷ 시작자 | **≥ 60%** | 산출물 3종 제출 확인 |
| G2 실사용 | 실제 지원 사용자 ÷ 완주자 | **≥ 50%** | D14 설문 + 4주 후 추적 |
| G3 재방문 | 종료 4주 후 재방문자 ÷ 완주자 | **≥ 40%** | 로그인 + 신규 경험 생성 |
| G4 지불의사 | 2기 유료 참가 의사 ÷ 완주자 | **≥ 30%** | D14 설문 (구체 금액 함께) |
| G5 병목 | 단계별 이탈 지점 특정 | 정성 | 관찰 기록 §9 |

### D14 회고 설문 (필수 문항)

1. 2주 중 **가장 막혔던 순간**은 언제, 어느 화면이었나요?
2. 포기하고 싶었던 적이 있나요? 무엇이 붙잡아 줬나요?
3. 만든 포트폴리오를 **실제 지원에 쓰실 건가요?** (예/아니오/이미 씀)
4. 아니라면 무엇이 부족한가요?
5. 이 프로그램이 유료라면 **얼마까지 내시겠어요?** (0원도 정상 답변)
6. 친구에게 추천하시겠어요? (0~10) — **6 이하면 이유를 반드시 받는다**
7. 제품에서 **없어도 됐던 기능**은 무엇인가요?

> 🎯 **7번은 인사담당자 면담의 28번 질문과 짝을 이룬다.** 심사자가 "안 본다"고 한 섹션과 참가자가 "없어도 됐다"는 기능이 겹치면 **즉시 제거 근거**가 된다.

## 12. 성공/실패 판정 (미리 정한다)

| 결과 | 조건 | 다음 행동 |
|---|---|---|
| ✅ **성공** | 완주율 ≥ 60% & 실사용 ≥ 50% | 2기 유료화 + 정규 프로그램화 |
| 🟡 **조건부** | 완주율 ≥ 60% & 실사용 < 50% | **산출물 품질 문제** → 인사담당자 면담 결과와 교차 분석 후 산출물 개편 |

> 마지막 줄이 중요하다. **사람이 매일 밀어주는데도 60%가 못 끝낸다면**, 그건 마케팅이나 동기부여 문제가 아니라 제품이 너무 무겁다는 뜻이다. 그 경우 2기를 하지 말고 §0의 감사 문서 §6-A(기본 경로 단순화)로 돌아간다.
