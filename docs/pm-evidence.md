# PM 경험정리: 제품 의사결정과 근거

2026-09-09 후속 개편: 아래 여섯 영역 요약을 보조 기록으로 보존하고, 핵심 경험 본문은 `pmWorkProducts`의 문제·대안·흐름·정책·실험·협업·문제 해결 산출물로 확장했다. 조사 출처·직군 구분과 현재 구조는 [PM 포트폴리오 조사 및 구현](./pm-portfolio-research.md)을 참고한다. 반복 인벤토리 화면은 제거했고 기존 결과의 재분석 버튼 이름은 'PM 산출물 다시 추출'이다.

## 설계 기준

기획/PM은 개발자의 커밋·코드처럼 파일 개수로 기여를 증명하기 어렵다. 따라서 산출물에서 **문제의 근거 → 비교와 선택 → 본인 실행 → 관찰 → 판단 변경**을 추출한다. 아래 여섯 영역은 채용 합격 점수나 인증 기준이 아니라 자료를 읽는 렌즈다. 모든 영역을 강제로 채우지 않으며, 출시 전 기획과 실패한 실험도 포함한다.

| 핵심 가치 | 읽을 자료 | 결과에 남길 것 |
| --- | --- | --- |
| 고객 문제 발견 | 인터뷰, VOC, 행동·퍼널 기록 | 문제를 선택한 실제 발화·관찰과 한계 |
| 우선순위와 포기 | 대안 비교, MVP 범위, 회의록 | 선택 기준, 채택·제외한 대안, 제약 |
| 설계와 실행 기여 | PRD, 정책·예외 흐름, 인수 조건 | 직접 작성·결정·합의한 범위와 팀 실행 구분 |
| 가설 검증 | 실험 계획, 사용성 테스트, 관찰 기록 | 사전 기준, 실제 실행·관찰, 유지·수정·중단 |
| 사용자·사업 변화 | 지표 보고서, 전후 비교, 정성 피드백 | 기준값·목표·관찰값, 기간·대상·방법 |
| 판단의 변화 | 회고, 가설 폐기, 후속 결정 | 예상과 달랐던 점과 다음 선택에 적용한 변화 |

근거: [GOV.UK Product manager 역량 체계](https://ddat-capability-framework.service.gov.uk/role/product-manager)의 사용자 인사이트·우선순위·가치·이해관계자 역량, [GOV.UK discovery 사용자 조사](https://www.gov.uk/service-manual/user-research/user-research-in-discovery)의 문제와 사용자 이해, [GOV.UK 서비스 편익 측정](https://www.gov.uk/service-manual/measuring-success/measuring-service-benefits)의 성과 측정, [SVPG의 네 가지 제품 위험](https://www.svpg.com/four-big-risks/)의 가치·사용성·실현 가능성·사업 타당성을 제품 요구사항으로 해석했다. 위 여섯 영역은 FitPoly의 구현 분류이며 이 기관들의 공식 평가 척도가 아니다.

## 추출 및 보호 장치

- 초안/전체 재분석의 PM 프롬프트에 `jobData.pmEvidence`(경험당 최대 12개), `pmMetrics`(최대 5개)를 추가한다. 같은 영역에서도 사용자 신호·범위 결정·정책·이해관계자 합의처럼 근거가 다르면 나눠 추출한다.
- 기존 AI 호출 결과를 서버에서 원문과 대조한다. 이를 위한 추가 AI 호출은 없다.
- 파일·링크의 구분 제목을 보존하고 발췌문을 공백 정규화 후 검색한다. 반환 출처와 행 번호는 **추출된 텍스트** 기준이며 PDF 원본 페이지 번호가 아니다.
- `source_excerpt`는 자료 원문에 존재함, `self_report`는 본인 입력·답변, `unlocated`는 원문 확인이 필요함을 뜻한다. 원문 일치는 내용의 진실성, 저자, 기여도 또는 인과효과를 보증하지 않는다. 요약·역할·단계의 의미 해석은 AI 추출이므로 제출 전 검토가 필요하다.
- 읽지 못한 링크, AI 추출 초안, 인터뷰 질문은 실행·성과 근거로 인정하지 않는다. 여러 파일에 같은 인용이 있으면 출처명으로 구분하지 못하는 한 미확인으로 남긴다.
- 목표와 관찰값을 별도 필드로 출력한다. 계획만 있는 인용에서는 실제 값을 제거하고, 수치는 원문에 있는 값만 남긴다. 실제 값은 관찰을 명시한 절에서 보수적으로 인식한다. 다양한 표현을 완벽하게 판정하지는 못하므로 실제 값도 미기록으로 남을 수 있다.
- Impact/Effort 점수는 원문에 1~5점이 명시된 경우만 사용한다. 기존 화면의 임의 좌표·지표 가산 휴리스틱을 제거했다.
- 화면의 여섯 영역 현황은 자료 연결 수이며 역량 점수가 아니다. 미확인 항목에는 보완할 자료·질문을 보여준다.

## 표시와 호환성

- 경험 결과 화면과 직군 특화 경험에 PM 전용 근거 사례를 표시한다.
- PM 화면을 프로젝트 맥락·역할, 의사결정 탐색, 판단별 원문, 관찰 결과, 보완 질문, 첨부 자료로 재구성했다. 기존 린 캔버스·서비스 타임라인·AS-IS/TO-BE·우선순위 매트릭스·별도 검증 대시보드와 접힌 기존 편집 화면을 제거했다. 해당 저장 필드를 운영 DB에서 삭제하지는 않았다.
- 기본 인쇄와 공통 포트폴리오·프로젝트 초안 내보내기도 같은 순서를 따른다. 원문은 화면에서 펼쳐 읽고 인쇄에서는 모두 표시한다. 판단 요약은 직접 수정할 수 있으며 원문 자체를 변경하거나 검증 상태를 높이지 않는다.
- 기존 결과의 서술은 새 영역에 그대로 배치하되 ‘기존 정리문 · 원문 대조 필요’로 표시한다. 이를 검증된 근거로 승격하지 않는다.
- 기존 결과를 근거가 검증된 것처럼 자동 승격하지 않는다. 원문 자료를 유지한 상태에서 전체 재분석해야 새 근거가 생성된다. 자유 보강은 원문 파일이 없는 경로이므로 이미 대조한 PM 근거를 유지한다.
- PM 이외 직군에는 PM 후처리를 적용하지 않는다. 개발자 Git 연동, 코드·아키텍처 추출 흐름은 변경하지 않는다.
- 실제 고객 자료, 유료 AI 호출, 운영 DB 수정, 배포는 이번 로컬 검증에 포함하지 않는다.

## 검증

저장소 루트에서:

```powershell
node --test backend/src/services/pmEvidence.test.js frontend/src/utils/pmEvidence.test.js
node backend/scripts/review-pm-evidence.mjs
```

브라우저 검증은 실행 중인 로컬 Vite 서버(`http://localhost:3000`)와 합성 자료를 사용하며 임시 폴더에 PC·모바일 스크린샷을 저장한다. 운영 로그인과 API 저장을 하지 않는다.

```powershell
cd frontend
npm run build
```
