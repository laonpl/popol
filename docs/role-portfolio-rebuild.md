확인일: 2026-09-10. 특정 기업의 채용 기준이나 익명 ‘합격 포트폴리오’ 판매 문구를 보편적 합격 공식으로 사용하지 않는다.

## 여러 기업의 역할 차이

PM은 [기존 다기업 비교 문서](pm-multi-company-framework.md)의 당근·쿠팡·채널톡·네이버웹툰·LY Corporation·Atlassian 자료를 유지하되, 위 공개 작업물과 함께 비교한다. 공통 축은 고객·사업 기회, 대안과 범위, 서비스 정책, 측정과 검증, 출시·운영 책임이다. 네이버웹툰 Growth 자료는 인접 직무의 실무 관점이며 전부 PM 채용 요건이라고 부르지 않는다.

마케팅은 다음 서로 다른 역할을 비교했다.

- [Converse Korea 브랜드 마케팅 공식 공고](https://careers.nike.com/professional-ii-brand-marketing-converse/job/R-89334): 소비자 인사이트, 브랜드 표현, 통합 캠페인, 에이전시·내부 협업, 예산, 브랜드 건강도. 검색에 노출된 공식 공고 본문을 확인했으나 직접 열기는 오류였으므로 장기 재검증 필요.
- [채널톡 DM 캠페인 실무 회고](https://docs.channel.io/team-blog/ko/articles/dm-marketing-lessons-learned-472ad18d): 기획 배경·대상·제작·실행·성과 해석과 회고를 함께 설명하는 당사자 사례. 채용 공고나 합격 후기와 구분.
- [airSlate Email Marketing Specialist](https://jobs.lever.co/airslate/e279e0d7-cfbd-4035-bd81-45d4fccae261): 세그먼트·개인화·행동 기반 워크플로·테스트·관찰 뒤 개선.
- [TodayTix CRM & Lifecycle Marketing](https://jobs.lever.co/todaytixgroup/6e90685e-0123-409b-b2d2-08f66fa4f149): 고객 생애주기와 반복 구매, 홀드아웃을 통한 증분 효과 구분. 리더급 조직 책임은 신입의 필수 조건이 아님.

이 비교로 마케터를 단일 전환 퍼널에 가두지 않는다. 브랜드·콘텐츠, 퍼포먼스, CRM의 실제 작업물만 표시하며 자동 직무 적합도·합격 점수는 계산하지 않는다.

## 실제 변경

### 2026-10-12: Figma·Notion 자료 연결과 한 장 포트폴리오

기본 화면은 경험 하나를 한 장으로 읽는 포트폴리오로 교체했다. 후속 피드백에 따라 본문의 Figma/PDF 뷰어를 제거하고, 자료 내부를 읽어 작성한 고객 문제·판단·실행 단계·검증 방법·관찰 결과를 본문에 표시한다. 좌측 소개·산출물 보관함은 유지하며 원본과 긴 제품/캠페인 리포트는 아래에서 펼친다. 대표 성과는 최대 4개이며 역할·배움·수치는 실제 자료에서 확인할 수 있는 내용만 넣는다.

- `자료로 경험 정리`: Figma 디자인/Slides의 텍스트 레이어와 이미지로 들어간 검증 화면을 읽는다. Notion 본문·표 및 경험에 명시적으로 연결한 보관함 파일 본문을 함께 분석해 제목·문제·판단/실행·검증·결과를 작성한다. 이전의 제목별 문단 복사는 이 흐름으로 교체했다. 시장 규모·경쟁사 성과를 본인 성과로 바꾸지 않으며, 자료에 없는 광고비·ROAS·개인 역할은 만들지 않는다. 수치가 부족해도 본문 작성은 진행한다.
- Figma REST 읽기에는 `file_content:read` 권한의 파일 읽기 토큰이 필요하다. 토큰은 읽기 요청에만 사용하고 저장하지 않는다. 토큰이 없으면 패널에서 Slides PDF·이미지를 가져와 같은 경험 정리를 실행할 수 있다. PDF는 기본 텍스트가 있어도 표·이미지 속 내용을 함께 읽도록 `readGraphics` 옵션을 추가했다. 원본 저장에 성공한 파일은 좌측 보관함에 추가하고 해당 경험에 연결한다.
- 본문에는 실제 수행 단계와 선택 이유, 검증 방법을 도식으로 표시한다. 원본 Figma/Notion/PDF는 아래 `정리에 사용한 원본 자료 확인`에서 접어 둔다. 기존의 ‘보강해 주세요’ 같은 안내문과 비어 있는 KPI 안내는 경험 본문에서 제거한다. AI가 일시적으로 응답하지 않으면 읽은 원문 발췌를 사용하며 기존 수치와 원본을 보존한다.
- 비공개 Notion은 페이지에 접근 권한이 있는 연결 토큰을 해당 읽기에만 사용한다. 토큰은 경험·브라우저 저장소·응답에 저장하지 않는다. 본문 요청은 인증된 사용자만 실행할 수 있고 고정 Notion 호스트, 읽기 시간·크기·트리 탐색 한도를 적용한다. 하위 페이지를 무작정 수집하지 않는다. 공개 프로토콜은 기존 앱의 방식과 현재 중첩 블록 응답을 지원하며 일부만 읽었을 때 표시한다.
- `수치 연결`: Google Sheets 공유/게시 링크의 CSV를 가져오고 사용자가 열을 연결해 반영한다. 저장된 연결은 버튼으로 실제 값을 갱신한다. CSV/TSV는 브라우저에서 읽어 집계한다. 광고 CSV는 CTR·CVR·CPA·ROAS를 원래 수량의 합계로 계산하고 산식과 채널별 집계를 표시한다. GA4/광고 계정의 OAuth 직접 연동은 구현하지 않았다.
- 대표 수치는 사용자가 선택하며 직접 입력도 가능하다. 퍼센트 변화량은 `%p`, 같은 단위의 수량은 실제 변화량으로 표시한다. 추이는 존재하는 관찰값만 그린다. 수치 연결 실패 시 기존 저장 값을 유지한다.
- 한 장 정리·자료 연결·수치 스냅샷은 `keyExperiences[].roleSummary`, `figmaConnection`, `planningConnection`, `sourceDocuments`, `performanceData`로 보존한다. AI 재분석 시 대응이 확실한 경험에는 유지하고 불확실하면 `roleSummaryArchive`에 남긴다. 이후 경험 분석과 공통 텍스트 내보내기에도 읽은 내부 본문과 정리 내용을 포함한다. 다른 경험에 연결한 파일을 임의로 혼합하지 않는다. 이전 상세와 편집은 유지한다.
- 최종 검증: 관련 단위 테스트 37개 통과. 제공한 실제 Figma의 7개 슬라이드를 읽기 전용으로 확인했다. 해당 텍스트와 검증 이미지에서 확인한 내용을 사용해 브라우저에서 PM·마케터 본문, 토큰 미저장, 저장/복원·내보내기·모바일, 분석 실패 시 기존 내용 보존, PDF 대체 입력과 보관함 연결을 확인했다. 브라우저의 API와 AI 응답은 모의 응답이며 실제 모델 요약 품질이나 Figma REST 인증 연동 성공을 검증한 것은 아니다. 실제 계정 저장·유료 AI 호출·운영 배포는 수행하지 않았다.
- 구현 근거: [Figma 공식 파일 내용 읽기 권한](https://developers.figma.com/docs/rest-api/authentication/), [Figma 파일/이미지 API](https://developers.figma.com/docs/rest-api/file-endpoints/), [Notion 공식 연결·권한 문서](https://developers.notion.com/guides/get-started/authorization), [Google Sheets 공유·게시 안내](https://support.google.com/docs/answer/183965?hl=en).
- 제공한 자료 내용과 모의 AI 응답으로 확인한 최종 화면: [마케터 한 장](role-portfolio-preview/source-experience-onepage.png), [PM 한 장](role-portfolio-preview/source-experience-pm-onepage.png), [A4 한 장 PDF](role-portfolio-preview/source-experience-onepage.pdf). PDF는 실제 생성한 파일을 다시 읽어 1페이지임을 확인했다. 프런트엔드 최종 빌드와 11개 경로 프리렌더, 백엔드 시작·건강 상태 및 새 라우트 인증도 통과했다.

### 2026-10-12: 직군별 시각화 캔버스로 본문 교체

좌측의 가벼운 소개와 산출물 보관함을 유지하고 PM·마케터 기본 본문을 다이어그램과 원본 작업물 중심으로 재구성했다. 좌측 판단 프로필과 본문의 긴 서술은 기본 화면에서 접고, 마케터도 좌측 보관함을 항상 볼 수 있게 배치했다.

- PM: 고객 관찰 → 문제 정의 → 채택·제외 대안의 클릭 가능한 의사결정 지도, MVP 범위 보드, 서비스 단계와 사용자·화면·운영·시스템·예외 레이어, 정책 → 인수 기준, 출시 타임라인, 실측 도넛/막대 지표, 검증 스토리보드와 회고 흐름. 실제 연결 이미지가 있으면 설계 장에서 프로토타입 갤러리를 표시한다.
- 마케터: 기록된 타깃 → 채널 → 다음 접점 지도, 원본 소재를 크게 보여주는 갤러리와 파일 선택, 문안 버전 비교, 콘텐츠 확장과 CRM 진입·메시지·종료 흐름, 단계별 실측과 실험·개선 스토리보드. PDF는 실제 첫 페이지를 렌더링하며 실패할 때 원본 열기를 제공한다.
- 지도 노드를 선택하면 상세 판단과 연결 원문을 읽는다. PC에서는 전체 연결을 본문 폭에 맞춰 표시하고, 좁은 화면에서는 캔버스 내부에서 이동한다. 인쇄에는 선택하지 않은 서비스 단계·소재와 접힌 원문도 포함한다.
- 퍼널의 폭은 같은 채널·기간·대상·단위의 감소하는 실측 수량이 있을 때만 비례한다. 조건이 다르거나 비율과 수량이 섞이면 단계별 실제 값을 동일 폭으로 표시한다. 기존 서술은 관련 장의 펼치기에서 보존하며 가상의 이미지·KPI를 만들지 않는다.
- 검증: 시각화 데이터 및 기존 비교 모델 테스트 12개, 실제 PM·마케터 컴포넌트의 합성 데이터 브라우저 점검에서 기록 추가·저장/복원·PDF/이미지·모바일 폭·읽기 전용·인쇄·내보내기 통과. 기존 원문·설명·정책 편집과 모의 파일 업로드 회귀, 프로덕션 빌드와 11개 경로 프리렌더도 통과했다. 실제 계정 저장이나 유료 AI 호출은 하지 않았다.

### 2026-10-12: 기본 결과 리포트 자체 재구성

직군별 입력 보완만으로는 결과 화면의 차이가 충분하지 않다는 피드백을 반영해 기본 본문을 교체했다. 이전의 단계 선택형 요약은 기본 화면에서 제거했다.

- PM 기본 리포트: 고객 문제와 인사이트 연결 → 선택·보류·미결정 MVP 보드 → 레이어별 서비스 설계도와 정책/인수 기준 → 출시 이정표와 조율 → 지표 비교·가설 검증 → 회고. 블루프린트가 없으면 실제 여정의 변경 전후를 사용한다.
- 마케터 기본 리포트: 캠페인 성과 헤더 → 브리프와 실제 작업물·카피를 나란히 표시 → 채널 집행/반응 비교표와 콘텐츠/CRM 운영 → 기록된 퍼널 단계와 지표 비교 → 실험 조건·최적화 기록. 전환·재구매·비용 성과가 있으면 대표 지표로 우선 표시한다.
- 그래프는 같은 단위를 가진 기준·실측·목표만 비교한다. 제작량은 고객 전환 퍼널에 넣지 않고, 캠페인 전체의 실측을 특정 채널이나 소재에 귀속하지 않는다. 채택·기각 여부나 흐름·지표가 없는 데이터는 창작하지 않는다.
- 기존 경험은 렌더링 시 새 구조를 사용한다. 서술형 기록은 관련 장에 유지하며 별도의 유료 분석 없이 읽을 수 있다. 기존 세부 기록과 수정은 ‘전체 추출 기록 · 원문 검토’에 보존한다. 각 새 장에서도 직접 기록을 추가할 수 있다.
- 새 리포트 자체를 인쇄하며 접혀 있는 기존 상세 문서를 중복 출력하지 않는다. 원본 파일 연결·설명·직접 기록과 공통 내보내기 계약은 보존한다.
- 검증: 새 데이터/도표 의미 테스트, PM·마케터 기본 리포트에서 직접 기록·직렬화 복원·원본 이미지·퍼널/설계도·모바일·인쇄·읽기 전용 확인, 기존 편집/파일 연결/내보내기 회귀, 프로덕션 빌드·프리렌더 확인. 브라우저 자료는 합성 데이터이며 실제 사용자 계정이나 유료 AI 호출은 사용하지 않았다.

### 2026-10-12: 직군별 입력부터 작업 기록·재분석까지 연결

- PM 입력은 고객 발견 근거, 우선순위와 포기한 대안, PRD·정책·제품 설계, 검증, 후속 결정으로 구성한다. 마케터 입력은 타깃·채널, 퍼널 병목, 메시지·소재 실험, 측정, 개선으로 구성한다. 자료 입력·인터뷰·빠른 기록·기존 경험 편집에 연결하며 작성한 답변만 원문으로 저장한다. 질문·예시는 실제 경험으로 저장하지 않는다.
- 핵심 장면 추출에도 선택 직군을 전달한다. 관련 사건 하나를 억지로 여러 사례로 나누거나 팀원의 개발 작업을 PM/마케터 본인의 작업으로 바꾸지 않도록 한다. 인터뷰의 기본 질문과 AI 장애 시 대체 질문도 직군별로 달라진다.
- 결과의 PM 의사결정 지도와 마케터 캠페인 보드에서 해당 단계의 산출물을 직접 추가한다. PM은 채택·기각 대안을 비교표로 읽고, 마케터는 채널별 고객·역할·다음 접점을 경로로 읽는다. 콘텐츠와 CRM이 함께 있어도 둘 다 탐색할 수 있다. 각 단계의 수는 저장된 작업 기록 개수다.
- 직접 입력은 본인 진술로 저장하며 계획·실행·관찰·개선 단계를 직접 선택한다. 참고 자료는 별도로 연결하고 외부 원문 검증으로 표시하지 않는다. 본인 진술의 관찰·기여·예산 필드는 원본 파일이 없다는 이유로 화면에서 사라지지 않는다. 수정·저장·복원·내보내기에 같은 내용을 사용한다.
- 재분석에는 현재 직접 입력과 선택한 단계를 전달한다. 삭제한 자료와 오래된 입력 스냅샷은 새 원문으로 재사용하지 않는다. 인터뷰 보강 시 첨부 자료·연결 설명·직접 기록과 이전 답변을 보존하며 AI 실패 때 기존 직군 리포트를 유지한다.
- 검증: 관련 단위 테스트 82개, 로컬 브라우저의 직군별 입력/직접 기록/직렬화 복원/내보내기/모바일/읽기 전용/인쇄와 기존 PM·마케터 리포트 회귀 확인. 프로덕션 빌드와 11개 경로 프리렌더 통과. 합성 데이터·모의 AI/API 응답만 사용했으며 실제 계정 저장·유료 AI 품질 평가·운영 배포는 수행하지 않았다.

### 2026-09-14: 마케터 핵심 경험 지도와 직접 보완

마케터는 긴 상세 문서를 기본 화면으로 제시하던 구조에서, 근거가 있는 대표 산출물을 읽는 요약 페이지 + 같은 페이지의 전체 기록으로 재구성했다. PM에 시험 적용했던 같은 형식은 사용자 피드백에 따라 직전의 제품 설계 문서 화면으로 복원했다.

- 마케터 기본 화면: 타깃과 장벽/약속, 대표 소재 문안, 채널 역할/예산/기간/다음 접점, 콘텐츠 운영/CRM 조건, 개선과 측정 해석. 전체 캠페인 성과를 소재의 성과로 연결하지 않는다. 원본 파일을 보여주는 곳은 상세의 작업물 영역으로 유지한다.
- 마케터 지도에서 ‘기록 확인’을 누르면 전체 산출물 영역이 열리고 해당 상세로 이동한다. 없는 상세는 보완 가능한 원본/검토 영역으로 이동한다. 인쇄에서는 접혀 있던 전체 기록도 포함한다. 단일 A4 분량을 강제하는 기능은 아니다. PM 상세는 직전처럼 항상 표시한다.
- 마케터 `WorkProductReview`에 ‘빠진 핵심 산출물 직접 정리’를 추가했다. 마케팅 필드로 작성하고, 이미 연결된 원문을 선택하거나 근거 미연결 초안으로 남긴다. PM은 직전처럼 추출된 산출물의 수정만 지원한다. 임의 출처는 승인하지 않는다. 마케터 수동 초안은 `userEdited`, `manuallyAdded`, `manualId`로 구분하고 실행 단계는 미확인으로 시작한다.
- 마케터 재분석은 대응하는 경험의 수동 추가 기록을 보존한다. 대응을 확정할 수 없는 기록은 `manualWorkProductArchive`로 남기며 다른 경험에 임의 연결하지 않는다. 해당 아카이브 복구 UI는 아직 없다. 수동 초안을 AI의 독립된 원문 증거로 재투입하지 않는다.
- 파일 보관/본문 추출 경로에 CSV/TSV를 연결했다. CSV/TSV는 기존 로컬 텍스트 파서를 사용하며 그 자체로 새 AI 호출이 없다. 광고 플랫폼/GA4 실시간 API 연동이 아니며 자동 ROAS 계산 기능도 아니다. 원본 저장 후 사용자가 재추출을 실행하면 분석 자료에 포함된다.
- 직무별 프롬프트에서 3~5종이 상한이 아님을 명시했다. 원문에 실제 규칙·문안·운영 조건·검증이 있으면 별도 산출물로 보존하고 없는 영역을 강제로 채우지 않는다.

### 2026-09-10: 직무별 페이지 구성 자체 분리

공통 ‘4개 요약 카드 → 자료 갤러리 → 지표 → 관점 탭’ 구성을 제거했다. 데이터 이름이나 색상만 바꾸는 방식이 아니라, 독자가 먼저 보는 산출물과 탐색 방식부터 다르다.

- PM: 제품 설계 문서. 좌측 프로젝트 정보/보관함 유지. 상단 동작 탐색기의 단계를 선택하면 그 단계의 고객 행동·화면·운영·시스템·예외를 읽는다. 이후 문제/리서치, 채택·제외 대안, 정책/인수 조건, 출시·조율, 검증 순으로 연속 문서를 읽는다. 서비스 블루프린트가 없으면 실제 여정 데이터 사용, 둘 다 없으면 가상의 흐름을 그리지 않는다. 정책과 단계는 임의의 인덱스로 연결하지 않는다.
- 마케터(후속 피드백 반영): 큰 소재 쇼케이스와 필름스트립을 제거하고 캠페인 사례 문서로 재구성했다. 목표·내 기여·운영 접점과 결과 요약을 먼저 읽는다. 이후 타깃과 메시지 → 문안 비교와 실제 작업물 → 채널/콘텐츠/CRM 운영 → 실험과 개선 순으로 이어진다. 원본 파일은 제작물 영역에서 한 번만 표시하며 추출 카피를 가상 포스터로 만들지 않는다. 채널도 선택형 화면 대신 전체 비교표로 읽는다. 우측 문서 목차는 좁은 화면에서 가로 목차가 된다. 밝은 배경과 작은 보라색 강조를 사용하고 큰 슬로건과 중복 갤러리를 없앴다. 상단 접이식 프로젝트 보관함·인쇄 메타데이터는 유지한다. PM의 레이아웃과 구현은 이 후속 수정에서 변경하지 않았다.
- 두 직군 모두 자료가 있는 장만 구성하며 기존 판단 기록·원본 연결·수정 기능은 보존한다. PM 원본/편집은 하단 전용 영역, 마케터 원본 관리는 제작물 장, 추출 필드 검토는 하단에 배치했다. 마케터 기존 정리문은 차원에 맞는 장에서 한 번씩 표시한다. 직무별 표현 컴포넌트는 별도이고 검증된 데이터/원본 관리 유틸리티만 공유한다.
- 사례/PM 서비스 단계 선택은 키보드로도 조작 가능하다. 인쇄에는 선택되지 않은 사례·단계, 모든 소재/채널, 접힌 측정 조건과 원문도 포함한다.
- 기존 추출문만 있는 경험은 즉시 새 레이아웃을 사용하지만 없는 서비스 흐름·시안·실측은 생기지 않는다. 해당 자료 추가 후 사용자가 ‘산출물 다시 추출’을 실행해야 새 구조 데이터를 얻는다. 화면 렌더링만으로 유료 재분석을 호출하지 않는다.

### 입력·저장·재분석·내보내기

- 새 업로드와 링크는 `deliverables`, 추가 추출 본문은 `additionalMaterials`, 경험별 원본 연결과 설명은 `keyExperiences[].artifactBindings`에 저장.
- 보관함 파일 추가 시 기존 파일 추출 API를 사용한다. 추가 본문은 파일당 20,000자·전체 60,000자 한도로 보존하고, 잘린 경우 사용자에게 알린다. 링크는 원본 열기용이며 자동 본문 분석을 수행하지 않는다.
- 저장 후 재추출 시 추가 본문도 입력된다. 제거한 추가 파일 본문은 재추출에서 제외한다. 파일을 경험에서 숨기는 것과 보관함에서 제거하는 것을 분리.
- AI 재추출 실패 시 기존 검토 결과를 유지한다. 재추출 성공 시 원본 연결은 ID 또는 유일한 제목이 맞는 경험으로 보존. 대응을 확정할 수 없는 설명은 `artifactBindingArchive`에 남기고 임의의 다른 경험에 배치하지 않는다. 현재 아카이브 복구 UI는 없음.
- 간략 보기, 핵심 경험 상세, 직군 포트폴리오, 공통 문서 내보내기에 반영. 원본 이미지도 내보내기 블록으로 포함. 인쇄는 모든 경험·산출물 관점을 포함.
- 마케터 v1의 부분 인용문 일치·타 파일 숫자 허용 방식 폐기. 전체 인용문과 유일한 출처를 대조하고 숫자는 해당 인용문 안에서 확인. 기존 수치는 원문 대조 전으로 보존하며 실측으로 표시하지 않음.
- 수동 수정은 원문을 바꾸지 않고 `userEdited`를 표시한다. 원문 대조는 인용문 위치 확인이며 내용의 진실성이나 인과의 자동 인증은 아니다.

### 2026-09-21 마케터 캠페인 사례 완성

- 실제 연결 파일을 먼저 보여주고 카피의 후킹·본문·CTA·선택 이유를 비교한다. 콘텐츠는 주제·독자 의도·배포/발행/재활용, CRM은 대상·트리거·발송/종료 조건, 채널은 역할·예산·기간·다음 접점으로 각각 표현한다. 모바일 채널 표는 카드처럼 읽힌다.

- 원문을 유지하는 서술형 판단 편집을 추가했다. 기존 typed 편집/직접 보완, 원본 연결·설명, 업로드·추출 경로는 유지한다. 기존 작업 이미지와 연결 이미지의 URL이 같으면 한 번만 표시하고 원본 데이터는 보존한다.
- 본문과 텍스트 내보내기는 `marketingCaseSections`의 같은 순서를 사용한다. 구형 정성 경험은 그대로 읽히며 기록 없는 광고 예산·KPI·가상 소재를 생성하지 않는다. 브랜드·콘텐츠·퍼포먼스·CRM 자료의 우선 추출 기준도 프롬프트에 명시했다.
