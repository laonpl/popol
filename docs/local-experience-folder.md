# 로컬 폴더에서 경험 정리

로컬 탐색기 v3는 바탕화면·문서·다운로드의 Windows 등록 경로를 별도로 탐색한다.
사전 경로 확인이 실패해도 대상을 버리지 않으며, 위치별 완료·접근 실패·문서 수를 표시한다.
탐색 및 첫 페이지 결과는 드라이브를 번갈아 처리해 한 드라이브에 편중되지 않는다.
HTML·마크다운 원문은 실행하지 않고 일반 문장으로 변환한 뒤 AI가 경험을 찾고 정리한다.

경험 정리 → **새 경험 추가 → 내 컴퓨터에서 찾기 → 내 컴퓨터 자동 찾기**에서 시작한다.
폴더·파일 선택 없이 로컬 탐색기가 사용자 폴더와 Windows 로컬 고정 드라이브의 문서를 찾고, **경험 찾기와 정리는 AI가 한다**(2026-11, 이전의 규칙 기반 분리·묶기·STAR 추출을 대체).

1. **읽기 순서**: 브라우저가 파일 이름·경로로 우선순위를 다시 매긴다(`prioritizeLocalFiles`). 기획서·보고서·발표자료·회고처럼 자세한 프로젝트 자료가 먼저, 이력서·자소서는 그다음, 강의자료·양식·대본은 뒤로 간다. `이력서 (1)`처럼 같은 파일의 사본은 가장 최근 것만 앞에 두고 나머지는 맨 뒤로 보낸다. 드라이브를 번갈아 읽고, 같은 프로젝트 폴더의 문서는 이어서 읽는다.
   - **회차 묶음**: 같은 폴더에서 숫자만 다른 회차 문서(`브릿지_1회차_…` ~ `브릿지_7회차_…`, `week 1` ~ `week 8`, `1차`·`2차`)는 한 묶음이다(`collapseSeries`, 최근 8개). AI 찾기에는 가장 최근 문서 하나만 보내고, 그 문서가 들어간 경험에 나머지 회차가 원문 자료로 함께 붙는다. 묶음은 읽기 한도(24개)에서 문서 하나로 센다.
   - **찾은 경험의 관련 자료**: 읽기 순서가 뒤라 이번 24개에 들지 못한 파일도 방금 찾은 경험의 자료로 보이면 바로 읽어 원문 자료로 붙인다(`relatedLocalFiles`, 경험당 4개, 자동 탐색에서만, AI 찾기 추가 호출 없음). 기준은 파일 경로다. ① 프로젝트 이름(제목의 ‘ — ’ 앞, 예: `FitPoly`)이 들어 있거나, ② 제목·원문 표현·AI가 준 검색어(`search`)의 고유 단어가 두 개 이상 들어 있으면 붙인다(예: 제목 ‘화재 대피 AI 내비게이션 — 시각장애인용 실내 대피 시스템’ → `구현트랙_보고서_시각장애인_실내대피_AI내비게이션.pdf`). ‘프로젝트’·‘보고서’·‘개발’ 같은 일반 단어는 세지 않는다. ③ 그렇게 붙은 파일과 같은 폴더의 다른 문서도 함께 붙인다(문서 6개 이하인 하위 폴더만, 예: 같은 폴더의 `구현_O2_발표자료.pdf`). 두 경험에 똑같이 맞는 파일은 붙이지 않고, 같은 문서의 사본·다른 형식(PDF/DOCX)·`v2`/`v3`는 하나만 읽는다. 붙인 파일은 다음 읽기 대상에서 빠지며, 다른 프로젝트 파일이 섞이면 정리 단계의 `unrelated`가 걸러낸다.
   - **다른 프로젝트 문서 차단**: AI가 한 경험에 묶은 문서 중 프로젝트 이름이 본문·파일 이름 어디에도 없는 문서는 서버가 뺀다(같은 대회에 낸 다른 프로젝트 신청서가 섞이는 것을 막는다). 이름이 나오는 문서가 하나도 없으면 AI의 묶음을 그대로 둔다.
   - **같은 사진 한 번만**: 사진마다 16×16 밝기 축소본을 만들어 거의 같으면(`sameLook`, 평균 차 3 이하) 같은 사진으로 본다. 한 문서 안에서, 그리고 한 경험에 붙은 문서들 사이에서(같은 발표자료의 사본·v2/v3) 한 번만 남긴다. 발표자료는 슬라이드마다 한 장씩 먼저 고른 뒤 같은 슬라이드의 둘째 사진을 고른다. 이름이 같은 자료를 붙일 때 `v2`/`v3`, `N차`, `(1)`만 다른 파일과 다른 폴더의 같은 이름 파일은 먼저 나온 하나만 읽는다.
   - **다른 프로젝트 파일 빼기(정리 단계)**: 정리 호출이 원문 파일 중 다른 프로젝트만 다루는 파일을 `unrelated`로 알려주면 그 파일과 사진을 경험에서 뺀다. 모든 파일을 빼라는 답은 무시한다.
   - **사진 제외**: 이력서·자소서·경력기술서 파일은 본문만 읽고 페이지 사진은 만들지 않는다. AI에 보낼 사진은 발표자료(PPTX)의 것을 먼저 고르며, AI도 이력서·지원서 페이지와 글만 있는 문서 캡처는 관련 없음으로 판단한다.
2. **본문·이미지 읽기(내 컴퓨터)**: 한 번에 문서 24개를 읽는다. 본문과 함께 DOCX(`word/media`)·PPTX(`ppt/media`, 슬라이드 글을 사진 설명으로 연결)·HWPX(`BinData`)의 그림과, 그림이 있는 PDF 페이지(최대 60쪽 안에서 8쪽)를 읽는다. 아이콘·로고·가는 띠 이미지(짧은 변 160px 미만 등)는 버리고 긴 변 1024px JPEG로 줄인다. 문서당 최대 8장. 같은 본문의 사본은 하나로 합치고 경로만 모두 남긴다.
3. **AI 경험 찾기** `POST /api/experience/local-discover`: 문서 본문(문서당 앞뒤 3천 자, 여러 경험이 담기는 이력서·자소서·포트폴리오는 7천 자)과 이미지 장수만 보낸다(이미지 자체는 보내지 않음). 서버가 약 3.6만 자씩 묶어 병렬로 AI(standard)에 보내 본인 경험을 찾고, 같은 프로젝트 문서를 묶고, 이력서 한 문서의 여러 경험을 나누고, 참고자료·양식·남의 사례는 제외 사유와 함께 돌려준다. 묶음이 여러 개거나 이미 찾은 경험이 있을 때만 AI(fast)가 같은 프로젝트끼리 한 번 더 합친다(묶음 하나는 찾기 호출이 이미 묶는다). 이 단계가 실패해도 찾은 경험은 따로 남긴다.
4. **AI 정리** `POST /api/experience/local-organize`: 화면에 보이는 경험(처음 5개, 더 보기·합치기·나누기 때 추가)마다 원문(합계 2.4만 자)과 문서 속 이미지 최대 6장(발표자료 먼저, 문서를 번갈아 고름)을 보낸다. 한도를 넘는 문서는 서버가 줄인다: 이력서처럼 이 경험을 일부에서만 다루는 문서는 프로젝트 이름·원문 표현이 나오는 대목과 그 뒤만 남기고, 문서 전체가 이 경험이면 앞뒤를 남긴다. **AI 호출은 경험당 한 번**이다. 이미지가 있으면 vision 티어가 이미지와 원문을 함께 읽어 이미지별 종류(성과·화면·구조도·활동 사진 등)·설명·보이는 글자·관련도·캡션과 제목·기간·역할·S·T·A·R·배운 점·핵심 한 줄·확인되지 않은 항목을 한꺼번에 채우고, 이미지가 없으면 standard 티어가 글만 읽는다. 원문에 없는 수치·결과는 쓰지 않고 빈칸과 `missing`으로 남긴다. 이미지를 읽는 호출이 실패하면 글로만 다시 정리한다. 직군별 심층 분석(6단계)은 그대로 deep 티어를 쓴다.
   - **결과 재사용**: 찾기·정리 요청은 문서·이미지를 파일 ID가 아닌 순번으로 보낸다(로컬 탐색기는 탐색할 때마다 ID를 새로 만든다). 응답은 요청 내용(문서 본문·이미지)의 SHA-256을 키로 이 브라우저의 `localStorage`(`fitpoly-local-ai-cache`, 최근 40건·14일)에 둔다. 같은 자료로 다시 찾거나 정리하면 AI를 부르지 않는다. 문서가 바뀌면 키가 달라져 새로 요청하고, ‘AI로 다시 정리’는 항상 새로 요청한다. 일부 묶음이 실패한 찾기 결과는 남기지 않는다.
5. **검토**: 카드에서 STAR를 고치고, 문서 속 이미지 중 경험에 넣을 사진을 고른다(AI가 장식·무관으로 본 것은 처음에 빠져 있음, 최대 6장 저장). 같은 경험이면 합치고(합친 뒤 다시 AI 정리), 다른 경험이면 나눈다(직접 합친 묶음은 원래 카드로, AI 묶음은 문서별로 다시 정리). ‘AI로 다시 정리’는 직접 고친 내용을 덮어쓰기 전에 확인한다. **다음 자료에서 경험 더 찾기**는 다음 24개 문서를 읽고, 이미 찾은 경험과 같은 프로젝트면 그 카드에 자료를 붙인다.
6. **직군별 분석 시작**: 고른 사진을 `/api/upload/image`로 올린 뒤(실패한 사진은 빼고 계속) 경험을 저장하고 기존 `/experience/analyze`로 분석한다. 저장 문서에는 `images`(URL·캡션·설명·출처, `localImage: true`)와 `content['문서 속 이미지 분석']`이 들어가 직군별 분석이 이미지에서 확인한 사실도 근거로 쓴다. 분석이 처음 성공하면 서버가 사진을 내용이 가장 겹치는 핵심 경험 옆(`keyExpImages`, 핵심 경험당 최대 3장)에 배치한다. 사용자가 이미 배치를 저장했다면 덮어쓰지 않는다. 결과 화면은 이 사진을 핵심 경험 사진으로, PM·마케터 한 장에서는 기획 산출물 사진 줄로 보여준다.

- 파일 탐색과 본문·이미지 추출은 내 컴퓨터에서 한다. 로컬 탐색기는 클라우드·AI를 호출하지 않는다. AI 찾기·정리 단계에서는 읽은 문서의 본문(상대 경로 포함)과 문서 속 이미지가 서버로 전송되고 크레딧을 사용한다. 원본 바이너리·절대 경로는 보내지 않는다. 계정 저장은 ‘직군별 분석 시작’을 눌렀을 때만 일어난다.
- AI 찾기·정리·분석 모두 로그인·크레딧·요청 제한(분당 30회)을 적용한다. 크레딧 부족·요청 제한·인증 오류가 나면 남은 정리를 멈추고 원인을 보여준다. 정리 중 ‘정리 멈추기’를 누르면 진행 중인 카드는 대기 상태로 돌아간다.
- 지원: TXT, MD, CSV, 텍스트 PDF, DOCX, PPTX, HWPX. 스캔 PDF·이미지 파일과 구형 HWP·DOC는 기존 가져오기를 사용한다.
- 파일당 25MB, 수동 선택은 한 번에 30개·합계 150MB, 본문 12만 자·PDF 200쪽까지 처리한다. 경험당 파일 이름을 포함한 원문 12만 자를 저장하며, 합친 자료가 이를 넘으면 분리하도록 안내한다.
- 숨김·시스템·개발 폴더, 다른 사용자 폴더, 네트워크 드라이브, 바로가기·심볼릭 링크는 제외한다. 자동 탐색은 문서 10,000개·전체 항목 250,000개·하위 40단계에서 멈추고 일부 위치를 확인하지 못했음을 표시한다. 보조 폴더 탐색은 문서 1,000개·전체 항목 10,000개·하위 32단계 한도를 적용한다.
- 직군별 분석의 실패·재시도 규칙은 그대로다. 일부 경험이 실패해도 저장한 경험 ID는 남고, 재시도는 기존 ID와 이미 올린 사진을 쓴다. AI의 핵심 경험 추출이 전부 실패하면 성공으로 저장하지 않고 `analysisFailure`에 원인 코드와 시각을 남긴다.
- `AI_CONFIGURATION`과 Bedrock 403 인증 오류가 발생하면 서버의 `AWS_BEARER_TOKEN_BEDROCK` 유효성을 확인하고 갱신 후 백엔드를 재시작한다. 키는 채팅이나 오류 응답에 노출하지 않는다.

localhost 개발 화면에서는 **내 컴퓨터 자동 찾기**를 누르면 Vite 개발 서버가 루프백 탐색 연결을 직접 준비한다. 별도 실행·다운로드·폴더 선택이 필요 없다. 브라우저가 로컬 네트워크 연결 권한을 요청하면 허용한다. 이미 실행 중인 호환 탐색기는 그대로 사용하며, 개발 서버가 직접 시작한 탐색기만 서버 종료 시 닫는다. 페이지를 열거나 개발 서버를 켜는 것만으로 파일을 탐색하지 않는다.
개발 전용 시작 경로 `/__fitpoly/local-experience/connect`는 같은 출처·루프백 접속·클라이언트 헤더가 모두 일치하는 POST만 허용한다. 배포 빌드에는 이 시작 경로를 제공하지 않는다.

배포 사이트에서도 **각 방문자 자신의 PC**에서 탐색한다. 사이트 운영자의 PC로 연결하지 않는다. 설치 없이 쓰려면 **설치 없이 폴더 접근 허용**을 누르고 본인 폴더를 허용한다. 추가 파일 선택 없이 허용한 폴더에서 STAR 경험 후보를 자동으로 찾는다.
Windows PC 전체 자동 탐색은 최초 한 번 다운로드 ZIP을 풀고 `FitPoly-자동연결-설정.cmd`를 실행한다. Node.js가 포함되어 있다. 현재 사용자 `%LOCALAPPDATA%\FitPoly\local-experience`에 설치하고 HKCU에 로그인 자동 시작 및 `fitpoly-local://connect` 앱 연결을 등록한다. `remove-connection.ps1`은 이 등록만 해제하고 설치 파일·원문은 삭제하지 않는다. 중지된 연결은 사이트의 **설정한 PC 연결 열기**로 시작할 수 있다. 브라우저의 앱 열기·로컬 연결 허용은 이용자가 직접 한다.
일시 실행만 원하면 `FitPoly-탐색기-실행.cmd`를 사용한다. 프로젝트의 `start.ps1`은 개발 서버만 켜고, 탐색 기능은 웹의 자동 찾기 버튼을 누를 때 준비한다.
수동 실행은 `node local-connector/server.mjs`다. 시작만으로 디스크를 탐색하지 않으며 웹에서 자동 찾기를 눌러야 탐색한다.
탐색기는 `127.0.0.1:43127`에만 바인딩하고, 고정된 FitPoly 출처·Host·세션 토큰을 검증한다. 세션에서 인덱싱한 ID만 읽고 절대 경로는 웹 응답에 포함하지 않는다.
[Chrome·Edge의 로컬 연결 권한](https://learn.microsoft.com/en-us/deployedge/ms-edge-local-network-access)에 따라 처음 연결할 때 브라우저의 허용 동작이 필요할 수 있다.
보조 폴더 선택은 [File System Access API](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)를 우선 사용하며, 미지원 브라우저에는 `webkitdirectory` 입력을 제공한다.

검증:

```powershell
cd frontend
npm.cmd run test:local-experience
npm.cmd run build
```

루트의 `node --test local-connector/connector.test.mjs`는 합성 디렉터리에서 자동 탐색·제외·중단·한도·경로 변경·출처/세션 검증을 확인한다. 실제 사용자 파일은 테스트하지 않는다.

기존 서버 파서(`shared/localExperienceParser.mjs`)는 파일 가져오기 경로에서 계속 쓰며, 회귀 검증은 `backend`의 `npm.cmd run test:import`로 실행한다.
`backend`에서 `node --test tests/localExperienceAI.test.js tests/localExperienceAnalysis.test.js tests/experienceAnalysisStatus.test.js tests/roleExperience.test.js tests/aiError.test.js`로 AI 찾기·정리 응답 정리, 사진 배치, 기존 직군별 분석 경로와 실패 시 보존을 검증한다.
개발 서버가 실행 중일 때 `backend`에서 `node scripts/review-local-experience.mjs`를 실행하면 그림이 든 합성 PPTX·DOCX·PDF와 모의 AI·계정 API로 문서 속 이미지 추출(아이콘 제외)·AI 찾기·정리·사진 선택·업로드·결과 화면 사진 표시·로컬 탐색기 경로·배포 사이트 연결 안내·모바일 화면을 검증한다. 실제 유료 AI 요청이나 계정 쓰기는 발생하지 않는다. 기본 주소는 `http://localhost:3000`이며 `LOCAL_REVIEW_ORIGIN`으로 바꿀 수 있다.
