# 로컬 폴더에서 경험 정리

로컬 탐색기 v3는 바탕화면·문서·다운로드의 Windows 등록 경로를 별도로 탐색한다.
사전 경로 확인이 실패해도 대상을 버리지 않으며, 위치별 완료·접근 실패·문서 수를 표시한다.
탐색 및 첫 페이지 결과는 드라이브를 번갈아 처리해 한 드라이브에 편중되지 않는다.
HTML·마크다운 원문은 실행하지 않고 일반 문장으로 변환한 뒤 경험을 나누고 편집·저장한다.

경험 정리 → **새 경험 추가 → 내 컴퓨터에서 찾기 → 내 컴퓨터 자동 찾기**에서 시작한다.
폴더·파일 선택 없이 로컬 탐색기가 사용자 폴더와 Windows 로컬 고정 드라이브의 문서를 찾는다.
이름·위치·수정일로 관련도를 정렬하되 대본·외부 조사·템플릿은 후순위로 보낸다.
최대 30개·150MB씩 읽고 본인이 직접 한 일이 드러나는 경험을 포함한다. 명사형 작업 기록이나 역할·성과가 부족한 기록도 ‘보완 필요’로 남긴다. 예시·외부 기업 사례·순수 참고자료는 계속 제외한다. 본인 기여가 기록된 시장 조사·영상 제작 경험은 포함한다.
STAR(상황·과제·행동·결과)를 분리해 추출·편집·저장하고, 결과 화면과 직군별 AI 분석에도 별도 과제 필드를 전달한다. 정량 성과가 없어도 정성 결과를 보존한다. 목표 수치·실행 예정·예시·빈칸은 실제 결과로 인정하지 않는다.
정리는 두 단계다. ① 문서 나누기: 이력서·자소서·포트폴리오·경험 정리(파일명·지원 동기 같은 문항, 기간이 적힌 서로 다른 항목 2개 이상, ‘프로젝트명:’ 2개 이상)만 경험 단위로 나눈다. 기획서·보고서·회고·회의록·발표자료 같은 그 밖의 문서는 통째로 한 프로젝트 자료로 본다. 모음 문서 안에서도 ‘서비스 소개’·‘프로젝트 회고’·‘01. 주요 기능’ 같은 소제목과, 기간·번호·프로젝트명 항목이 있는 문서의 키워드 줄은 나누는 기준으로 쓰지 않는다. ② 프로젝트 묶기: 모든 문서 쌍을 비교해 복사본 → 프로젝트명·제목·주차 시리즈·공통 본문 → 같은 폴더 순으로 강한 근거부터 연결한다. 읽는 순서와 관계없이 같은 결과가 나오며, 프로젝트명(없으면 ‘~프로젝트/서비스’ 제목)이 서로 다른 묶음은 중간 문서를 거쳐도 합치지 않는다. 묶음 제목은 본문 프로젝트명 → 프로젝트형 제목 → 공통 폴더 이름 → 문서 제목 → 파일명 순으로 정하고, 기간은 가장 이른 시작부터 가장 늦은 날짜까지로 잡는다.
같은 이름의 프로젝트 자료는 출처를 유지하며 묶고, 역할 기록과 결과 기록이 서로 다른 문서에 있어도 합쳐서 판단한다.
공통 문장이 없어도 구체적인 작업 대상·구현 내용이 양쪽 원문에서 충분히 겹치고 같은 수치·성과가 확인되면 프로젝트 단위로 융합한다. `3만 건`/`30,000건`을 같은 수치로 읽으며 날짜·도구만 같다는 이유로 합치지 않는다. 원문에 실제 표기된 `QRious (큐리어스)` 같은 별칭만 이름 차이의 근거로 인정한다. 명시적으로 다른 프로젝트·조직과 사용자가 나눈 후보는 계속 분리하고, 문맥 연결은 그룹 전체의 직접 근거를 확인해 종합문서의 연쇄 병합을 막는다.
융합된 STAR는 중복·완전히 포함되는 원문 문장만 정리하며 별도 기여·성과·소수점 수치와 모든 파일별 원문을 보존한다. 확인된 동일 프로젝트가 커도 카드 자체는 하나로 유지하지만 저장·분석의 원문 12만 자 제한은 그대로 적용한다. 추가 탐색 후에는 대표 ID 하나만 비교하지 않고 원문 조각과 leaf ID로 기존 카드를 찾아 갱신해 중복 카드를 남기지 않는다. 실제 편집값만 보존하고 새로 찾은 자료의 기여·결과도 함께 반영한다. 계정에 저장된 경험은 자동 수정·삭제하지 않으며 신규 자료가 붙은 완료 카드는 기존 분석 결과임을 구분해 표시한다.
같은 프로젝트 폴더(예: `바탕화면/포트폴리오/쇼핑몰 리뉴얼/`, 하위 `발표/`·`자료/` 포함)의 문서는 이어서 읽고 하나의 경험으로 묶어 함께 분석한다. 바탕화면·문서 같은 위치 폴더, 자소서·포트폴리오·공모전 같은 모음 폴더, 문서 20개를 넘는 폴더, 여러 경험이 든 문서, 서로 다른 프로젝트명이 확인된 문서는 폴더만으로 묶지 않는다. 제목이 파일명뿐이면 폴더 이름을 제목으로 쓴다.
‘xx 보고서 1주차’·‘xx보고서 2주차’·‘xx 중간보고서’·‘xx 최종보고서’처럼 주차·회차·차수·단계만 다른 문서는 폴더가 달라도 같은 프로젝트로 묶고 제목은 ‘xx’로 정리한다. ‘제3회·제4회 공모전’ 같은 대회 회수, ‘주간 보고서’처럼 프로젝트 이름이 없는 시리즈, 자소서 차수, 여러 경험이 든 문서의 파일명은 이 규칙을 쓰지 않는다.
자동 찾기와 수동 파일 선택 모두 같은 묶기 규칙을 쓴다. 파일 제목이 달라도 본문의 실제 프로젝트명이나 구체적인 공통 작업 문단이 일치하면 같은 경험으로 묶는다. 임의 영단어를 고유 이름으로 추측하지 않으며, 기술명·연락처·일반 파일명만 같다는 이유로 합치지 않는다. 공통 문단은 수행한 작업을 포함하고 양쪽 문서에서 충분한 비중을 차지해야 한다. 내용·폴더 연결은 묶음 전체에서도 확인해 중간 문서를 통한 연쇄 병합을 막고, 폴더 자료에도 프로젝트 이름 또는 구체적인 작업 대상 일치를 요구한다. 병합 근거와 복사본을 포함한 파일별 원문 출처를 보여주며 **다른 경험이면 묶음 나누기**로 되돌릴 수 있다.
‘담당했습니다.’ 같은 서술어 조각·자소서 문항명이나 `B2B`·`HIGHLIGHTS`·`Marketing` 같은 단독 분류·섹션명은 제목으로 쓰지 않는다. `{프로젝트명}` 같은 빈칸, `생산관리>품질관리` 같은 메뉴 경로, 글머리표·마침표로 시작하는 조각, 글자 없는 날짜 조각(`.16 ~ 2026-05.17`), ‘언어의’처럼 조사로 끝나는 한 단어도 제목으로 쓰지 않으며 이런 제목끼리는 같은 경험으로 묶지 않는다. 코드·JSON·연락처는 제목과 STAR 필드 추출에서 제외하고 원문 출처는 보존한다. 포트폴리오 소개·연락처 문단을 별도 경험으로 만들지 않는다. `2026.05.16`·`5월 16일`처럼 일까지 적은 날짜도 기간으로 읽는다.
‘~한다·~중요하다·~책이다’ 같은 현재형 일반 설명과 ‘영화로 제작되었다’ 같은 남의 일 수동형은 내가 한 행동·결과로 인정하지 않는다. `{지원 직무}` 같은 빈칸이 2개 이상이거나 ‘출력 형식:’·‘기본 양식’·‘작성 요령’이 있는 문서는 템플릿, 독후감·서평(파일명 또는 저자·줄거리·작품 같은 표지 3개 이상)은 참고자료로 제외한다. 주소(URL)는 문서끼리 묶는 고유 이름으로 쓰지 않는다. 원문의 프로젝트명, 설명에 실제 등장하는 서비스명, 유효한 파일명을 순서대로 확인한다. 확인되지 않으면 경험은 보완 후보로 유지하고 제목을 직접 확인하도록 한다. 지원 포부·미래 계획은 실제 행동에서 분리한다.
경험 5개를 찾았다고 중단하지 않고 한 번에 최대 240개 문서를 확인해 뒤쪽 경험과 관련 자료도 수집한다. 자기소개·지원서 문서의 경험 본문과 이력서의 명사형 작업 기록도 검토한다. 근거가 풍부한 경험을 먼저 정렬하고 5개를 펼치며, 총 경험 수와 전체 제목 목록을 위에 표시한다. 숨겨진 경험은 유료 분석 대상으로 자동 선택하지 않는다.
정렬은 원문으로 뒷받침되는 구체적 기여·판단 과정과 실제 정량·정성 성과를 우선하며, 상황·과제와 제목 출처를 보조로 평가한다. 숫자 없는 정성 결과도 추천할 수 있고, 파일 수·본문 길이·키워드 반복이나 원문에 없는 입력 결과에는 가점하지 않는다. 자동·수동 선택 모두 같은 순서로 정렬하고 `추천 경험`과 근거를 표시한다. 편집 중에는 카드가 이동하지 않으며, 추가 탐색 후에는 편집값·선택ID를 보존하면서 전체 추천순으로 다시 정렬하고 선택한 카드가 숨지 않게 펼친다.
제목에서는 `기간`·`내 역할` 등 필드명과 `해커톤 팀의 백엔드/AI 개발자로 참여하여` 같은 역할 설명·연결절을 제외한다. 본문의 명사형 캠페인·플랫폼 이름을 파일명보다 우선하고, 긴 메타데이터 뒤의 제목과 한 줄 PDF 카드도 처리한다. 본문에서 고른 설명형 제목은 `source_description` 출처를 보존하며 그 설명만 같다고 서로 다른 경험을 병합하지 않는다.
참고자료와 근거 부족 자료는 입력 카드 대신 접힌 제외 사유 목록으로 표시한다. 적격 경험이 적으면 개수를 억지로 채우지 않는다.
아직 읽지 않은 문서는 **다음 자료에서 경험 더 찾기**로 이어간다. 관련도는 규칙 기반이며 자료가 실제 본인의 경험인지는 후보 화면에서 확인한다.
특정 폴더만 탐색하는 기존 방식은 접힌 보조 옵션으로 유지한다.
후보 화면에서 제목·기간·역할·상황(S)·과제(T)·행동(A)·결과(R)·선택적인 배운 점과 원문을 확인한다.
같은 경험의 자료는 후보를 선택해 하나로 합칠 수 있다. 동일 본문 복사본은 자동으로 묶는다.
직군·경력 단계·핵심경험 수를 고른 뒤 **직군별 분석 시작**을 누르면 기존 `/experience/analyze`로 이어진다.
한 경험을 분석하면 기존 경험 결과 화면으로 이동하고, 여러 경험은 각 후보의 **직군별 핵심경험 결과 보기**에서 연다.

- 자동 탐색은 루프백 로컬 탐색기에서 실행하고 텍스트 추출·규칙 기반 후보 생성은 브라우저에서 무료로 실행한다. 로컬 탐색기는 클라우드·AI를 호출하지 않는다.
- 분석 시작을 눌렀을 때 선택한 경험 내용·추출 원문·상대 경로를 기존 경험 API로 저장한 뒤, 기존 직군별 AI 분석을 호출한다. AI 단계는 기존과 동일한 크레딧·권한·요청 제한을 적용한다. 원본 바이너리·절대 경로는 보내지 않는다.
- 사용자 검토 내용과 파일별 원문을 분리해서 전달한다. 공통 후보를 `reviewedMoments`로 고정하지 않아 AI가 직군별 판단 장면을 여러 개 추출한다. 직군별 스키마와 원문 대조 규칙은 기존 분석기를 그대로 사용한다.
- 원본 파일을 수정하지 않는다. 분석 전에는 파일 핸들과 본문을 화면의 메모리에만 유지한다. 새로 방문하면 자동 찾기를 다시 누르고, 보조 폴더 모드에서는 폴더를 다시 선택한다. 분석을 시작한 경험의 추출 원문은 계정에 보존된다.
- 지원: TXT, MD, CSV, 텍스트 PDF, DOCX, PPTX, HWPX. 스캔 PDF·이미지와 구형 HWP·DOC는 기존 가져오기를 사용한다.
- 파일당 25MB, 한 번에 30개·합계 150MB, 본문 12만 자·PDF 200쪽까지 처리한다. 경험당 파일 이름을 포함한 원문 12만 자를 저장하며, 합친 자료가 이를 넘으면 분리하도록 안내한다. AI 프롬프트에는 기존 분석기의 입력 한도(필드당 2만 자, 전체 4만 자 및 앞뒤 보존)를 적용한다.
- 숨김·시스템·개발 폴더, 다른 사용자 폴더, 네트워크 드라이브, 바로가기·심볼릭 링크는 제외한다. 자동 탐색은 문서 10,000개·전체 항목 250,000개·하위 40단계에서 멈추고 일부 위치를 확인하지 못했음을 표시한다. 보조 폴더 탐색은 문서 1,000개·전체 항목 10,000개·하위 32단계 한도를 적용한다.
- 일부 문서를 읽거나 분석하지 못해도 결과와 저장한 경험 ID는 남는다. 재시도에서는 기존 ID를 사용하고 완료된 경험을 제외한다. 계정·요청 제한이나 AI 장애 시에는 나머지 작업을 멈춘다. 중단 버튼은 진행 중인 한 경험을 마친 뒤 다음 경험을 시작하지 않는다.
- AI의 핵심 경험 추출이 전부 실패하면 성공으로 저장하지 않는다. 원문·기존 결과를 보존하고 `analysisFailure`에 원인 코드와 시각을 남긴다. 인증·요청 제한·시간 초과·응답 형식 오류를 구분하며 실패 응답에는 AI 사용량 과금을 확정하지 않는다. 일부만 성공하면 성공한 경험과 누락 안내를 제공한다.
- `AI_CONFIGURATION`과 Bedrock 403 인증 오류가 발생하면 서버의 `AWS_BEARER_TOKEN_BEDROCK` 유효성을 확인하고 갱신 후 백엔드를 재시작한다. 키는 채팅이나 오류 응답에 노출하지 않는다. 원문이나 경험을 새로 만들 필요는 없다.
- 문서에 없는 성과는 채우지 않고 빈칸으로 남긴다. 경험 구분이 불확실하면 검토 표시를 하고, 저장한 경험은 `needs_confirmation` 상태다.

localhost 개발 화면에서는 **내 컴퓨터 자동 찾기**를 누르면 Vite 개발 서버가 루프백 탐색 연결을 직접 준비한다. 별도 실행·다운로드·폴더 선택이 필요 없다. 브라우저가 로컬 네트워크 연결 권한을 요청하면 허용한다. 이미 실행 중인 호환 탐색기는 그대로 사용하며, 개발 서버가 직접 시작한 탐색기만 서버 종료 시 닫는다. 페이지를 열거나 개발 서버를 켜는 것만으로 파일을 탐색하지 않는다.
개발 전용 시작 경로 `/__fitpoly/local-experience/connect`는 같은 출처·루프백 접속·클라이언트 헤더가 모두 일치하는 POST만 허용한다. 배포 빌드에는 이 시작 경로를 제공하지 않는다.

배포 사이트에서도 **각 방문자 자신의 PC**에서 탐색한다. 사이트 운영자의 PC로 연결하지 않는다. 설치 없이 쓰려면 **설치 없이 폴더 접근 허용**을 누르고 본인 폴더를 허용한다. 추가 파일 선택 없이 허용한 폴더에서 STAR 경험 후보를 자동으로 찾는다.
Windows PC 전체 자동 탐색은 최초 한 번 다운로드 ZIP을 풀고 `FitPoly-자동연결-설정.cmd`를 실행한다. Node.js가 포함되어 있다. 현재 사용자 `%LOCALAPPDATA%\FitPoly\local-experience`에 설치하고 HKCU에 로그인 자동 시작 및 `fitpoly-local://connect` 앱 연결을 등록한다. `remove-connection.ps1`은 이 등록만 해제하고 설치 파일·원문은 삭제하지 않는다. 중지된 연결은 사이트의 **설정한 PC 연결 열기**로 시작할 수 있다. 브라우저의 앱 열기·로컬 연결 허용은 이용자가 직접 한다.
일시 실행만 원하면 `FitPoly-탐색기-실행.cmd`를 사용한다. 프로젝트의 `start.ps1`은 개발 서버만 켜고, 탐색 기능은 웹의 자동 찾기 버튼을 누를 때 준비한다.
수동 실행은 `node local-connector/server.mjs`다. 시작만으로 디스크를 탐색하지 않으며 웹에서 자동 찾기를 눌러야 탐색한다.
탐색기는 `127.0.0.1:43127`에만 바인딩하고, 고정된 FitPoly 출처·Host·세션 토큰을 검증한다. 세션에서 인덱싱한 ID만 읽고 절대 경로는 웹 응답에 포함하지 않는다.
[Chrome·Edge의 로컬 연결 권한](https://learn.microsoft.com/en-us/deployedge/ms-edge-local-network-access)에 따라 처음 연결할 때 브라우저의 허용 동작이 필요할 수 있다.
보조 폴더 선택은 [File System Access API](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)를 우선 사용하며, 미지원 브라우저에는 `webkitdirectory` 입력을 제공한다.

검증:

```powershell
cd frontend
npm.cmd run test:local-experience
npm.cmd run build
```

루트의 `node --test local-connector/connector.test.mjs`는 합성 디렉터리에서 자동 탐색·제외·중단·한도·경로 변경·출처/세션 검증을 확인한다. 실제 사용자 파일은 테스트하지 않는다.

기존 서버 파서는 공유 모듈을 사용하면서 직군 프로필 주입을 유지한다. 회귀 검증은 `backend`의 `npm.cmd run test:import`로 실행한다.
`backend`에서 `node --test tests/localExperienceAnalysis.test.js tests/experienceAnalysisStatus.test.js tests/roleExperience.test.js tests/aiError.test.js`로 기존 직군별 분석 경로와 파일 원문 전달·출처·소유권·AI 실패 시 보존·부분 성공·인증 오류를 검증한다.
개발 서버가 실행 중일 때 `backend`에서 `node scripts/review-local-experience.mjs`를 실행하면 합성 문서와 모의 계정·AI API로 추출·합치기·분석 재시도·PM/개발자 결과 화면 연결·모바일 화면·폴더 입력 대체 경로를 검증한다. 실제 유료 AI 요청이나 계정 쓰기는 발생하지 않는다.
